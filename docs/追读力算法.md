# 追读力算法

> 引擎：`src/novel_writer/core/reading_power.py` → `ReadingPowerTracker`
> 落盘：`{project}/reading_power.json`
> 调用点：写后沉淀 `workflow/sediment.py`（每章自动 analyze+record）；上下文组装 `workflow/context.py`（`build_guidance` 注入下一章）
> 测试：`tests/test_reading_power.py`

## 一句话总结

把「读者愿不愿意追下一章」量化成 **钩子类型 × 强度 + 爽点 + 微兑现 + 阅读债务** 四类指标，逐章落盘、滑窗统计，并据此生成下一章的写作指导。

## 指标体系

### 钩子（Hook）— 5 类

| 类型 | id | 关键词族 |
|------|----|----------|
| 危机钩 | `crisis` | 危险/死/杀/逃/追/攻击/爆炸/崩塌/坠落 |
| 悬念钩 | `mystery` | 秘密/真相/谜/奇怪/诡异/不可思议/为什么/到底 |
| 渴望钩 | `desire` | 想要/渴望/追求/梦想/希望/等待/期待 |
| 情绪钩 | `emotion` | 愤怒/悲伤/绝望/感动/心碎/泪/笑/恨 |
| 选择钩 | `choice` | 选择/抉择/两难/要么/必须/不得不/放弃 |

**主类型** = 命中次数最多的那一类；**强度** = 该类命中次数：

| 命中次数 | `hook_strength` |
|----------|-----------------|
| ≥5 | `strong` |
| ≥2 | `medium` |
| <2 | `weak` |

### 爽点（Cool-point）— 8 类全集

声明全集（`COOL_POINTS`）：打脸反转 / 底牌揭示 / 逆袭胜利 / 权威挑战 / 反派落败 / 甜蜜惊喜 / 迪化误解 / 身份掉马。

**自动检测覆盖全部 8 类**（关键词任一命中即记），词表在 `core/text_signals.py`：

| 类型 | 关键词 |
|------|--------|
| 打脸反转 | 打脸/嘲讽/不屑/小看/碾压 |
| 底牌揭示 | 底牌/隐藏/真正/其实/原来 |
| 逆袭胜利 | 逆袭/翻盘/反杀/绝地/逆转 |
| 权威挑战 | 挑战/掌门/长老/宗主/不敬/以下犯上/对抗/权威 |
| 反派落败 | 报应/活该/罪有应得/落败/崩溃 |
| 甜蜜惊喜 | 惊喜/意外/礼物/好运/幸运/甜蜜/温柔 |
| 迪化误解 | 误会/误解/脑补/以为/曲解/误以为 |
| 身份掉马 | 掉马/身份/暴露/真面目/揭穿/识破/摊牌 |

### 微兑现（Micro-payoff）— 4 类

| 类型 | 关键词 |
|------|--------|
| 信息 | 得知/发现/明白/了解/知道 |
| 能力 | 学会/掌握/突破/领悟/觉醒 |
| 关系 | 信任/结盟/友谊/和解/认可 |
| 资源 | 获得/得到/收获/宝物/功法 |

### 阅读债务（Debt）

`ChapterReadingPower.debt_balance` 为章节级字段，**当前 `analyze_chapter` 不会自动计算债务**（恒为 0.0）。债务应由审校/LLM 反馈写入，`get_debt_total()` 对全书求和。

## 得分公式

```
score = 60                              # 基准
      + (15 if strong else 8 if medium else 0)   # 钩子强度
      + len(cool_points) * 5
      + len(micro_payoffs) * 3
score = clamp(score, 0, 100)
```

## 写作指导生成（`build_guidance`）

取最近 3 章 + 滑窗 10 章统计，按以下规则产出指导行（无命中返回空串）：

| 规则 | 触发条件 | 指导文案 |
|------|----------|----------|
| 钩子多样性 | 某钩子类型占比 >50% | 尝试其他类型 |
| 爽点节奏 | 最近 3 章零爽点 | 本章至少安排一个爽点 |
| 微兑现密度 | 最近 2 章零微兑现 | 本章给读者小回报 |
| 债务警告 | `debt_total > 5` | 尽快安排回报 |
| 得分趋势 | 最近 3 章得分差 <−10 / >+10 | 提升吸引力 / 保持节奏 |

## 数据结构

```python
@dataclass
class ChapterReadingPower:
    chapter: int
    hook_type: str              # 主钩子类型 id
    hook_strength: str          # strong / medium / weak
    cool_points: list[str]
    micro_payoffs: list[str]
    hard_violations: list[str]  # 硬违规（预留，自动分析不填）
    soft_suggestions: list[str] # 软建议（预留）
    debt_balance: float         # 阅读债务
    score: float                # 0-100
```

落盘为 `reading_power.json`（`asdict` 列表，按 chapter 排序，同章去重覆盖）。

## 与其他模块的口径共享

| 共享项 | 对端 | 约定 |
|--------|------|------|
| 钩子/爽点/微兑现关键词表 | **唯一来源 `core/text_signals.py`**；[质量检查算法](质量检查算法.md) 同 import | 改词只改 `text_signals.py` |
| `build_guidance` 输出 | [分层上下文组装算法](分层上下文组装算法.md) Tier 2 | 叙事记忆层注入「【追读力指导】」 |
| `record()` 调用 | [写后沉淀算法](写后沉淀算法.md) | 每章正文写完后自动 analyze + record |

## 边界与已知限制

- 关键词法有误报（如「他笑了」可能只是配角表情），也有漏报（无关键词的高级钩子）。
- `hard_violations` / `soft_suggestions` / `debt_balance` 自动链路**不产生**，需外部写入。
- `record()` 是**同章覆盖**而非追加，重跑沉淀会覆盖上一次结果。

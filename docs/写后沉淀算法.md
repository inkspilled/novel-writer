# 写后沉淀算法

> 引擎：`src/novel_writer/core/workflow/sediment.py` → `sediment_chapter(project_dir, chapter, content, llm_data=None)`
> 调用点：工作流 runner 在该章**全部章后步骤（含润色）完成后**自动调用（`_run_sediment`），读取最终落盘正文；断点键 `sediment_{n}`
> LLM 主通道：`runner._llm_sediment`（每章 +1 次 LLM 调用，提示词见 `build_memory_sediment_prompt`）
> 落盘：`memory.json` + `reading_power.json` + `story_threads.json`（台账对账）

## 一句话总结

每章章后步骤完成后自动提取记忆：**LLM 语义提取为主通道**（状态变化/伏笔开关/读者承诺/关系/世界规则 + 按 subject 精确回收伏笔），LLM 不可用或失败时**正则兜底**；章节事件、四维追踪、追读力两路共用。

## 沉淀管线

```
最终落盘正文（润色后）
  │
  ├─► ⓪ LLM 沉淀（_llm_sediment → apply_llm_sediment）
  │      character_state / open_loops / resolved（精确回收）
  │      reader_promises / relationships / world_rules
  │      失败 → None → 走下方正则兜底
  │
  ├─► ①a 状态变化抽取（正则兜底） ──► memory.character_state
  ├─► ②a 伏笔线索抽取（正则兜底） ──► memory.open_loops
  ├─► ③ 章节事件记录（两路共用） ──► memory.story_facts
  ├─► ④ 四维追踪（两路共用） ─────► memory.{resources,emotional_arcs,info_boundary,subplots}
  │         (chapter_tracker.track_all，维度级隔离)
  ├─► ⑤ 伏笔回收：LLM 路=resolved 按 subject 精确关闭；
  │      正则路=回收信号词检测（_auto_close_loops）
  ├─► memory.compact() + save()
  │
  ├─► ⑥ 反模式过期清理 ─► anti_patterns.json（clear_resolved）
  │
  ├─► ⑦ 追读力分析 ────► reading_power.json
  │         (ReadingPowerTracker.analyze+record)
  │
  └─► ⑧ 故事线台账对账 ─► story_threads.json
            (runner._sync_story_ledger：open_loops/subplots/story_facts + world_state.timeline)
            纯规则、失败不判定沉淀失败
```

## LLM 主通道（`apply_llm_sediment`）

提示词要点（`build_memory_sediment_prompt`）：注入当前未解伏笔列表（≤15 条，供精确回收）；铁律「只记录确定发生的事，假设/心理活动/口头『如果…就…』不算」。输出 JSON 结构：

| 字段 | 去向 | 备注 |
|------|------|------|
| `character_state` | character_state 桶 | {subject, aspect, value} |
| `open_loops` | open_loops 桶 | subject 自动生成 `第{n}章伏笔{i}·{摘要24字}`（与正则同约定） |
| `resolved` | `close_loop(subject, n)` | subject 须与注入列表逐字一致；同时写 story_facts 回收记录 |
| `reader_promises` | reader_promises 桶 | 尾部「读者承诺」展示位的数据源 |
| `relationships` | relationships 桶 | 中部「关系与世界规则」块的数据源 |
| `world_rules` | world_rules 桶 | 同上 |

LLM 输出不可信，逐条防御性校验（非 dict/空字段跳过、字符串截断）。返回非 JSON / 调用异常 / 无可用 Agent（按 剧情审查→校对→第一个 Agent 找）→ 返回 None 走正则兜底。

## 各步口径（正则兜底 + 共用）

### ①a 状态变化 → `character_state`（正则兜底）

| 方面 | 正则 | 示例 |
|------|------|------|
| 实力变化 | `X(突破\|晋升\|升级\|进阶)` | 凌尘突破 |
| 身体状态 | `X(受伤\|重伤\|濒死\|死亡\|陨落)` | 凌尘受伤 |
| 位置变化 | `X(到达\|来到\|离开\|前往\|回到)` | 凌尘来到 |

主体长度限制 2–6 字。`value` 为整个匹配串。

### ②a 伏笔线索 → `open_loops`（正则兜底）

| 模式 | 示例 |
|------|------|
| `竟然\|居然\|原来\|没想到\|殊不知` + 5–40 字 | 竟然发现灵脉异常 |
| `如果\|倘若\|万一` + 5–40 字 | 如果那枚玉佩是真的… |

- `subject` = `第{ch}章伏笔{序号}·{摘要24字}`（含序号+片段，**同章多伏笔互不覆盖**）
- `aspect` = `悬念`
- `value` 截断 60 字
- `payload.urgency = 0.6`（埋设初值；注入上下文时按动态公式重算，见[因果相关性算法](因果相关性算法.md)）

### ③ 章节事件 → `story_facts`

- `subject` = `第{ch}章 {标题}`（标题取正文第一个 Markdown 标题，无则 `第{n}章`）
- `value` = 首段前 100 字

### ④ 四维追踪

委托 [章节四维追踪算法](章节四维追踪算法.md) 的 `track_all`。失败仅 debug 日志，不中断。

### ⑤ 伏笔回收

- **LLM 路**：`resolved` 数组按 subject 精确关闭（提示词注入了未解伏笔列表），可靠；
- **正则路**（兜底）：`_auto_close_loops` 正则匹配回收信号词（「原来如此」「真相大白」「谜底揭开」「终于明白」等）→ 提取信号上下文 → 与 `open_loops` 的关键词（2-4 字中文片段）子串匹配 → 命中自动 `close_loop`。漏报可接受（注意力尾部持续提醒），误报有审计链可追溯。

### ⑥ 反模式清理

`AntiPatternTracker.clear_resolved(chapter)`：high 永不过期；medium/low 距今 >10 章清除。
失败仅 debug 日志，不中断沉淀。

### ⑦ 追读力

委托 [追读力算法](追读力算法.md)。失败仅 debug 日志。

### ⑧ 故事线台账对账

沉淀落盘后由 `runner._sync_story_ledger(n)` 调用
[故事线台账](故事线台账算法.md)：把本章新埋/已回收伏笔、支线进度、世界状态时间线
对账进 `story_threads.json`，并发 `story_track` 事件刷新 UI。纯规则、零 LLM；
它自带异常兜底，且放在 `sediment_{n}=done` 之后，台账失败不会让整章沉淀被判定失败。

## 标题提取（`extract_chapter_title`）

扫描正文行，匹配 `^#{1,3}\s+(.+)$`，清理 `*_`#\[]()` 等符号，截断 50 字。找不到返回 `第{n}章`。

## 压缩时机

`mem.compact()` 在 `save()` 前调用——见[长期记忆算法](长期记忆算法.md)。保证每次沉淀后 outdated 链不会无限膨胀。

## 边界与已知限制

- LLM 主通道每章 +1 次 LLM 调用（与 world_state_update 同量级）；单 Agent 配置下由该 Agent 兼任（`_fallback_agent` 语义）。
- 状态变化正则兜底的主体 `\w+` 噪声大（实测「不能让他突破」曾被当成实力变化）——这正是 LLM 主通道存在的理由，正则只保证"LLM 挂了记忆不断流"。
- 追读力/四维追踪的失败被吞（debug），生产排障需开 debug 日志。
- 沉淀是**幂等的同章覆盖**（memory 同键覆盖、reading_power 同章覆盖），重跑安全但会丢失上一次的 outdated 审计细节（被 compact 清掉）。
- 反模式清理阈值固定 10 章（见[反模式追踪算法](反模式追踪算法.md)）。
- 沉淀时机在润色之后、读取最终落盘正文——记忆描述的是读者实际看到的文本；原因与断点语义见[因果相关性算法](因果相关性算法.md)。
- 沉淀失败不中断章节循环：不标记 `sediment_{n}`，断点恢复时自动重试；LLM 沉淀降级为正则不算失败（照常标记 done）。
- 四维追踪（resources/emotional/info/subplots）仍为正则，是下一批 LLM 化候补（见[章节四维追踪算法](章节四维追踪算法.md)）。
- 台账对账只读 memory/world_state、只写 `story_threads.json`，不会反向修改沉淀结果。

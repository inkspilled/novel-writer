# 短剧素材与 ComfyUI

短剧「资产」页登记人物 / 场景 / 道具三类素材，并负责把它们生成为参考图。

## 资产 ↔ 小说正典

资产不是独立的一套数据，而是**指向小说正典的引用**：

| 资产类型 | 数据来源 | 关联字段 |
|---|---|---|
| 人物 `character` | `canon/characters.json`（角色卡） | `entity` = 角色 `id` |
| 场景 `location` | `world_state.json` 的 `locations` | `entity` = 地点名 |
| 道具 `prop` | `world_state.json` 的 `items_catalog` | `entity` = 物品名 |

资产记录结构（`drama/assets/index.json`）：

```json
{
  "kind": "character",
  "id": "char_顾言",
  "name": "顾言",
  "prompt": "顾言，人物设定参考图，……",
  "ref": "generated/char_顾言.png",
  "status": "ready",
  "notes": "从小说导入",
  "entity": "c1",
  "image": "generated/char_顾言.png"
}
```

- `entity` 是回指正典的键：人物优先存角色卡 id，退化为名称；
- `ref` 给 UI 显示，`image` 是生成图相对路径（两者生成后一致）；
- 表格里没有 `entity` / `image` 列，但**保存时会按 id 合并保留**，不会丢关联。

## 来源：正典 vs 短剧原创

资产表里 `source` 三种，回答「这行是从哪来的」：

| source | 含义 | 怎么产生 |
|---|---|---|
| `canon` | 小说正典里有 | 「从小说导入」；或分镜里的名字**匹配上了**角色卡/地点/物品 |
| `storyboard` | **短剧原创**（小说里没有） | 分镜提取时匹配不上：龙套、临时茶棚、一次性道具 |
| `manual` | 手工登记 | 「＋ 资产」 |

所以出现两种来源是**设计如此**，不是重复：

- 主角/主要场景必须挂 `canon`，改小说设定时以正典为准；
- 龙套和临时场景挂 `storyboard`，`entity` 为空，**允许存在，也不强行塞回小说**。

匹配规则（`match_canon_entity`）：名称归一化（去空格、去「（主角）」这类括号注解）后
精确匹配；再按角色 `aliases` 做包含匹配。命中即回填 `entity`（人物用角色卡 id），
未命中才标原创。

## 一致性怎么保证

1. **同一 `(类型, 归一化名称)` 只留一行**：导入与分镜提取都幂等，重复点不会翻倍；
2. **导入只补缺、不覆盖**：手改过的提示词、已生成的图不会被「从小说导入」冲掉；
3. **保存按 id 合并**：表格里没展示的 `entity`/`image` 不会因为点保存而丢失；
4. **正典改名会暴露出来**：`canon` 资产的 `entity` 对不上任何人时进「正典失联」，
   用「检查资产」列出来，确认后改 `entity` 或删行；
5. **原创资产不参与正典校验**，只要求能生成图，不要求和小说人物表对齐；
6. **重新生成分镜不覆盖旧版**：旧 JSON 进 `storyboard/versions/`，手工改表格不落历史。

## 资产体检（「检查资产」）

| 维度 | 含义 | 处理 |
|---|---|---|
| 来源分布 | 正典 / 原创 / 手工 各多少 | 判断是不是分镜跑出来的龙套太多 |
| 缺提示词 | `prompt` 为空 | 点「生成提示词」 |
| 缺参考图 | `image` 为空 | 点「生成图片」 |
| 定妆不齐 | 人物缺头肩角度 | 「生成图片」续跑 |
| 全身不齐 | 人物缺全身正/侧/背 | 「生成图片」续跑 |
| 环景不齐 | 场景缺环景或透视 | 「生成图片」续跑 |
| 三视图不齐 | 道具缺正/侧/背 | 「生成图片」续跑 |
| 提示词风险 | 类型锚词缺失 / 场景道具混入人像词 / 无描述兜底 / 多实体名 / 固定特征没写左右 | 改提示词，重生成前先修 |
| 画幅不符 | 出图实际比例和类型画幅对不上（`needs_crop`/`needs_check` + `aspect_warning`） | 先裁切/确认再拿去用，别直接做首尾帧；裁好后把状态改回 `ready`、更新定妆图路径 |
| 正典失联 | `canon` 资产 entity 找不到对应角色/地点 | 改名/删行/重新导入 |
| 重名 | 归一化后同名 | 删掉重复行 |

状态口径：`draft`（刚登记）→ `ready`（已生成图）。没有「剧情质量评分」——
短剧资产只保证**形象可用、和正典不打架**，不评价画风好坏。

### 导入

「从小说导入」调用 `DramaStore.sync_assets_from_canon()`：

- 默认导入**人物 + 地点**（`kinds=("character","location")`）；
- 按 `(kind, 归一化名称)` 去重，重复点不会生成重复行；
- 道具条目可能有上百个，需要时传 `kinds=("character","location","prop")` 再导。

分镜页的「提取资产」（`extract_assets_from_storyboard`）是另一条路：
按分镜的角色/地点列补登记——能对上正典的标 `canon` 并回填 entity，
对不上的标 `storyboard`（短剧原创）。

## 画幅：按类型出图（人物 / 场景 / 道具）

三类资产用途不同，画幅也不同——统一竖屏会把场景画成"人站在门口"，道具也没有特写感：

| 类型 | 画幅 | 像素 | 提示词里的画幅句 | 负面词 |
|---|---|---|---|---|
| 人物 `character` | 3:4 竖屏（即"4:3 竖屏"） | 960×1280 | `画幅 3:4 竖构图（宽:高=3:4）` | `ASSET_NEGATIVE` |
| 场景 `location` | 2:1 环景 | 2048×1024 | 360° 等距柱状投影 | 前置「人物，人影，人脸，手」 |
| 道具 `prop` | 1:1 方图 | 1024×1024 | `画幅 1:1 方构图（宽:高=1:1）` | 前置「人物，人影，人脸，手」 |

宽高**既**通过 `width/height` 传给 ComfyUI / 图片 API，**也**写进正向词：
接口或工作流模板丢参数时，模型仍能按文字画对画幅（`ASSET_PROMPT_PLANS`）。
像素值都是 16 的倍数（latent 对齐）。

### 三层参考图（人物两层、道具三视图）

- **人物·头肩定妆**：四角度（正面/左侧/右侧/正后方），管脸部一致性；
- **人物·全身三视图**（`_fb_` 前缀）：正面/侧面/背面全身立像，管姿态和服装；
  首尾帧生成按景别分层取用——远景/全景/中景优先全身参考，特写/近景用头肩定妆；
- **道具·三视图**：正面/侧面/背面，侧面和背面以正面照为同一物品基准；
  单张特写只看得到一个面，视频里道具一转就穿帮；
- 场景不变：360° 环景 + 自动投影的正向/反向透视。

每组「侧面/背面」都引用同层正面照生成（无参考工作流时报错，不静默降级）；
正面照重生成会重新开始一组，旧图进 `versions/` 并登记索引。

## 提示词怎么来

`DramaStore.asset_prompt(asset)`：

- **手填优先**：`prompt` 非空就原样用；没写画幅会补一句 `画幅 3:4 竖构图（宽:高=3:4）`，
  保证文字和 `width/height` 参数一致；
- 否则按「名称 + 类型 + 正典摘要 + 题材 + 风格 + 类型后缀」拼，例如：
  `顾言，人物妆发参考图，主角；外形：白衣，仙侠题材，短剧人物妆发定妆照，3:4 竖构图，正面单人头肩特写，保留完整发饰和肩线，柔和均匀的日光`。左侧、右侧和正后方均以正面照为参考分别生成；
- 负向词按类型走 `ASSET_PROMPT_PLANS[kind]["negative"]`：场景/道具在
  `ASSET_NEGATIVE` 前加「人物，人影，人脸，手」。
  **注意**：内置工作流 CFG=1，负向词实际不生效——类型/外观约束必须写进正向词
  （模板已按正面式表述设计）；要真正用负面词需把 CFG 调到 3–7。
- 企划页「配色」`series.palette` 非空时追加 `配色：…`：配色在画第一张图前定死，
  同时进生图提示词与七段式视频提示词。
- 图片 API 若支持独立负面词字段，在 `image_generation` 配置里设
  `supports_negative_prompt: true`；否则退回「避免：…」附在正向词末尾（已知降级）。
  ComfyUI 路径虽有负面词节点，但内置模板 CFG=1 时不生效。

「生成提示词」按钮只补**空提示词**的行，不会覆盖手改。

## 接入 ComfyUI

### 1. 准备一个「API 格式」工作流

在 ComfyUI 里搭好流程（加载 checkpoint、LoRA、采样器、SaveImage 等），
用 **Save (API Format)** 导出 JSON（不是界面导出那种 `nodes/links` 结构）。

把需要按资产变化的三处输入改成占位符：

| 占位符 | 填到哪个节点 | 说明 |
|---|---|---|
| `{{positive}}` | CLIPTextEncode 的 text | 正向提示词 |
| `{{negative}}` | 负面 CLIPTextEncode 的 text | 负向提示词 |
| `{{seed}}` | KSampler 的 seed | 每张随机；整个值就是占位符时会替换成整数（ComfyUI 只认 int） |
| `{{prefix}}` | SaveImage 的 filename_prefix | 用资产 id，方便回查 |
| `{{width}}` / `{{height}}` | EmptyLatentImage | 按资产类型传：人物 960×1280、场景环景 2048×1024、道具 1024×1024 |

例：

```json
"6": {"class_type": "CLIPTextEncode",
      "inputs": {"text": "{{positive}}", "clip": ["4", 1]}},
"3": {"class_type": "KSampler",
      "inputs": {"seed": "{{seed}}", "steps": 20, "cfg": 7, ...}}
```

### 2. 填地址与模板

「设置 → 模型设置 → 图像生成（ComfyUI）」：

- **ComfyUI 地址**：默认 `http://127.0.0.1:8188`；
- **工作流模板**：上面导出的 `workflow_api.json`。

存到 `data/config.json` 的 `comfyui` 段：

```json
"comfyui": {"base_url": "http://127.0.0.1:8188", "workflow": "D:/ai/comfy/workflow_api.json"}
```

### 3. 生成

资产页选中若干行（不选 = 全部）→「生成图片」：

```
ComfyUIClient.generate()
  ├─ load_workflow(template)          # API 格式 JSON
  ├─ fill_workflow(占位符替换)
  ├─ POST /prompt {prompt, client_id} # 返回 prompt_id
  ├─ 轮询 GET /history/{prompt_id}     # 1s 一次，默认 300s 超时
  └─ GET /view?filename=…             # 下载图片字节
```

拿到字节后 `DramaStore.save_generated_image(asset_id, data, expected_size=...)`：

- 写入 `drama/assets/generated/{asset_id}.png`；
- **新版本存新文件**：重生成时旧图先移到 `generated/versions/{asset_id}_{时间戳}.png`，
  不覆盖不删除（重生成的不一定比旧的好，留着一起挑）；
- 读**真实像素**（PNG/JPEG/GIF/WebP 头）记到 `image_size`；和类型画幅比例差超过 2%
  标 `needs_crop`、读不出尺寸标 `needs_check`，并写 `aspect_warning`；
  这类图**不会设为定妆图**，避免错误比例被固化，但图不删（先留着裁）；
- 回填 `image` / `ref`，尺寸正常时 `status` 置 `ready`；
- 表格自动刷新，参考图列显示路径；「检查资产」会列出画幅不符的行。

单张失败不打断整批（记日志继续），全失败才报错。

## 交给 ComfyUI：批次包（素材 + 提示词 + 工作流）

资产页「导出 ComfyUI 批次」按当前配置的 ComfyUI 工作流导出
`drama/exports/comfy_batch_时间戳/`：

```
manifest.json      # 每个资产的提示词/负面词/尺寸/seed/参考图/工作流路径
workflows/         # 占位符已填好的 API 格式工作流，可直接 Load → Queue
images/            # 定妆图/参考图拷贝，包自包含
prompts.md         # 人看的提示词清单
README.md          # 用法与注意事项
```

- **画幅**按类型写入 `width/height`（人物 960×1280、场景环景 2048×1024、道具 1024×1024）；
- **种子**用 `asset_seed()`，和直连生成同一套算法，重跑可复现；
- 人物任务是 4 张头肩定妆 + 3 张全身三视图（前缀 `{资产}_fb_{角度}`）；
  道具是正/侧/背三张；任务前缀就是资产 ID（+ 角度），`depends_on` 标出
  「先跑正面、再把该图上传为 `reference_input`」的顺序；
- 有 `reference_image` 的资产自动走参考图工作流，参考图拷到 `images/`，
  工作流里填文件名（先上传到 ComfyUI 的 `input/`）；
- 比例不对（`needs_crop`）的图**不进批次**，避免把错误比例固化；
- 模板里没有 `{{width}}`/`{{height}}` 时，`manifest.workflow_size_placeholders=false`，
  README 会明确警告「画幅由模板固定、软件传的尺寸不生效」；
- 没配工作流也能导：只输出提示词、素材和清单，`workflows/` 为空；
- 本包只负责资产参考图；每镜视频提示词走分镜页「导出视频提示词」。

### 手工批次跑完：把结果回流进项目

资产页「导入生成结果」选择出图目录（批次包 `images/` 或 ComfyUI 的 `output/`），
按**文件名前缀**对回资产/首尾帧，走和直连生成完全相同的落盘与画幅核对：

- `{资产}.png` → 通用参考图；`{资产}_{正面|左侧|右侧|正后方}` → 头肩定妆；
- `{资产}_fb_{正面|侧面|背面}` → 全身三视图；`{资产}_panorama` → 场景环景；
- `{资产}_{正面|侧面|背面}`（道具） → 道具三视图；`{镜号}_{first|last}` → 首尾帧；
- ComfyUI 重名追加的计数后缀（`xxx_00001_.png`）也能识别；
- 画幅不对的照常报错但不停整批，结尾列出失败与没认出前缀的文件。

## 生成记录：这张图怎么来的

每次出图/出视频都往 `drama/generation_records.jsonl` 追加一条：
目标、服务与模型、工作流文件及 hash、seed、提示词与负面词摘要、参考图 digest、
输出文件 digest、时间（`core/drama_records.py`）。资产页「生成记录」按选中资产
查它的完整配方；seed 是确定性算法（`asset_seed`），换机器可复现。
旧图进 `versions/` 时同步登记 `drama/versions_index.jsonl`，历史对得上号。

## 公用素材库：能复用就不重画

龙套、临时茶棚、通用道具这类素材各剧长得都差不多，每次重画是纯浪费。
公用素材库在**用户级数据目录** `data/drama_library/`（`index.json` + `images/`），
跨项目共享（`core/drama_library.py`）。

**复用（生成前，AI 判定）**

- 「生成图片」时自动先问库：只有 `source=storyboard/manual`（短剧原创/手工登记）的资产参与；
  **正典资产是独有设定，一律不复用**；
- AI 一次合并调用判定整个批次（省 token）：有独有细节（纹身、特定陈设、具名身份）不复用，
  **拿不准就不复用，宁可重画**；没配模型退回本地名称匹配；
- 命中即**拷贝**库图进项目 `assets/generated/library/`（不引用项目外路径，项目可整个搬走），
  记 `library_id` 追溯；**跳过出图和提示词审核**（根本没有出图这回事），
  但视觉审核 + 「确认公用库复用」照走——库图进来也要人看过才算数；
- 资产页「匹配公用库」可对选中行手动触发同一判定。

**回存（生成后，AI 判定 + 手动）**

- 生成完的原创资产，AI 判定哪些是通用素材（通用路人才收，独有设定不收），
  自动存入库；只收**成组完整**的视图（四张定妆、三张全身、三张三视图、环景全套）；
- 资产页「存入公用库」手动入库不依赖模型，同样要求成组；库里已有同类型同名条目时跳过；
- 「检查资产」会统计当前项目复用自公用库的资产数（`from_library`）。

## 首尾帧与本集视频（ComfyUI）

### 首尾帧说明

「短剧工作流 → 首尾帧提示词」逐集写 `drama/keyframes/epNNN.json`：
每镜 `first_frame` / `last_frame` / `motion`，体检缺镜、首尾同图、动作太短。
分镜页「导出首尾帧批次」= `export_comfy_batch(episode=本集, include_assets=False)`，
每镜两个任务，画布 720p（9:16 → 720×1280）。

### 生成本集视频

视频入口要求先有首尾帧图、故事/画风确认和逐镜提交前审核；材料改动后重审。
不再在视频提交中静默生成图片。审核通过后逐镜调用 ComfyUI 或 Seedance。
「制作本集视频」会自动接续上述阶段，再做后期、全片复核和复盘。
详见 [短剧制作工作流](短剧制作工作流.md)。

## 文件落在哪：Comfy 生成，软件取回落盘

ComfyUI 的工作流只会把结果写进**它自己的 output 目录**（由 ComfyUI 启动参数决定，
默认 `ComfyUI/output/`）。软件不是让 Comfy 直接写项目目录，而是：

1. 提交 `/prompt`，轮询 `/history`，再从 `/view` 把字节取回；
2. 写进当前小说项目：
   - 资产图 → `drama/assets/generated/`（旧版进 `versions/`）
   - 首尾帧 → `drama/keyframes/epNNN/{镜号}_first|last.png`
   - 视频片段 → `drama/videos/epNNN/{镜号}.mp4`，整集 `drama/videos/epNNN.mp4`
3. Comfy 自己 output 里的那份**不删**（两边各留一份）。

所以：**软件内生成 = 自动复制进项目**；**手工跑导出的批次包 = 只落在 Comfy 的 output**，
要进项目得手动拷回，或用软件内「生成图片 / 生成本集视频」重跑一次。

预览：资产页选中行即时显示参考图、双击看大图；分镜页「预览本集」可对照首尾帧并播放整集
（QtMultimedia 内嵌播放，失败可回退系统播放器）。

## 其他生成服务与后期

- 图片设置还支持图片 API 与 Codex CLI；参考图通过编辑接口/一致性工作流/`-i` 传入，不能静默忽略。
- 视频设置可选择 ComfyUI 或 Seedance。
- 后期支持按目标时长剪辑、转场、调色、放大、配乐/字幕和切点抽帧，保留原片段和后期版本。

# 地点身份与坐标

当前实现：`core/location_identity.py`、`core/world_state.py`；入口：「世界 → 地点」。

## 身份与去重

地点沿用标准名称与稳定 `location_id`，其他称呼记录在 `aliases`，所属区域记录在 `parent`。新输出先做 Unicode/空白规范化与唯一别名匹配，再计算世界状态增量，避免把地点改称误记为角色移动。歧义别名不自动匹配。同名子地点应使用带区域的标准名，如「甲城·东门」「乙城·东门」。

现有重复地点通过「检查重复并合并到已有地点」处理：名称＋描述转换为本地字符二元组词频向量，按余弦相似度排序，排除已明确属于不同区域的候选。这是无 API 成本的文字相似候选，不是语义理解或重复认定。选择合并目标后保留目标 ID，原名作为别名，统一人物/物品位置、时间线与地点进出流水引用。合并前写 `world_state.before_location_merge.json` 备份。

## 坐标约定

- `coordinates`：二维 `[x,y]` 或三维 `[x,y,z]`，只能是有限数值。
- `coordinate_frame`：明确的空间坐标系名称，例如「青云宗平面图」。同一系的原点、轴向和比例由作者统一规划。
- `coordinate_unit`：例如米、千米或格；同一个坐标系必须统一单位和维数。
- 地点可以不填坐标；不随机分配，也不从章节顺序猜测地理位置。

只有同一坐标系、同一单位、同一维数时才计算欧氏距离。不同坐标系返回未知，不擅自建立转换。坐标接近不表示同一地点：同一栋楼内可以有多个房间。

世界状态抽取和正文上下文携带已有地点、别名、所属与已规划坐标，要求复用现有地点。未来可在本地候选基础上加入 embedding 重排、显式交通图和移动耗时检查；当前尚未实现自动地图布局、跨坐标系变换或全书地理一致性证明。

# 项目存储与文件格式

> 引擎：`src/novel_writer/core/project_io.py`、`src/novel_writer/core/app_config.py`、`src/novel_writer/models/`
> 性质：`规范`（文件约定，改动需同步代码与文档）

## 一句话总结

基于目录的项目存储：每本小说一个文件夹，章节/规划/灵感/审校各归其位；原子写入防崩溃丢数据；章节文件名带序号+标题，支持任意位数。

## 目录布局

```
data/projects/{project_name}/
├── meta.json              # 项目元信息
├── chat.db                # 可选：聊天记录 SQLite（save_chat_history=true）
├── world_state.json       # 大世界状态
├── story_threads.json     # 故事线台账（时间线/主线/支线/伏笔 + 进度）
├── canon/world_state.checkpoint.json  # 事件投影 checkpoint
├── memory.json            # 长期记忆（11 桶）
├── anti_patterns.json     # 反模式库
├── reading_power.json     # 追读力数据
├── rag_index.json         # RAG 索引（若持久化）
├── workflow.json          # 工作流进度（断点恢复）
├── planning/              # 规划文档（.md）
│   ├── 立意.md / 大纲.md / 章节细纲.md / 人物设定.md
│   ├── 世界观.md / 时间线.md / 主线.md / 支线.md / 伏笔.md
│   └── 目录.md            # 自动生成
├── chapters/              # 章节正文
│   ├── 1_第一章.txt        # 正文
│   ├── 1_第一章.outline.md # 细纲
│   ├── 1_第一章.summary.md # 概要
│   └── versions/          # 封印后修订版本（index.json 指向最新）
├── inspiration/           # 灵感记录（.md）
├── review/                # 审校报告（.md）
├── summary/               # 剧情摘要（.md）
├── skills/                # 项目自定义技能包（覆盖 config/内置）
├── runs/                  # 工作流运行日志（*.jsonl，append-only）
├── canon/                 # 正典层
│   ├── events.jsonl       # append-only 事件（known_by/hidden/hash chain）
│   └── characters.json    # 角色注册表（档位/状态/知识冻结）
└── sim_cache/
    ├── sim_{n}.md          # 作者侧推演
    └── pov/{char}/         # 角色侧 POV 推演（隔离视图）
```

## 文件格式约定

| 类型 | 格式 | 说明 |
|------|------|------|
| 章节正文 | `.txt` | 纯文本，不需要 Markdown 语法 |
| 章节概要 | `{n}_{title}.summary.md` | 自动结构化卡片 |
| 全书章节细纲 | `planning/章节细纲.md` | 逐章剧情骨架（`## 第N章` + 事件/转折/钩子）；工作流分批生成，编辑器防抖自动保存 |
| 单章细纲 | `{n}_{title}.outline.md` | 可选，单章展开稿 |
| 规划文档 | `.md` | 有结构层级 |
| 运行日志 | `runs/{时间}-{pid}-{工作流名}.jsonl` | 只记步骤/耗时/token/工具事件，不落正文 |
| 技能包 | `skills/*.md` 或 `skills/*/SKILL.md` | frontmatter：`name` / `description` / `when_to_use` |
| 灵感/审校/摘要 | `.md` | |
| 故事线台账 | `story_threads.json` | `version/meta/threads`；四类线程（timeline/main/subplot/foreshadow），`id` 为 `kind+title` 稳定哈希，`user_edited` 保护手工字段 |

**章节序号**：变宽数字，**不补零**（`1_xxx.txt`），支持任意位数。文件名正则 `_CHAPTER_RE` 解析 `number + title`。

## 流水账选型：JSON 还是 SQLite

存储分两类，不要混：

| 类型 | 例子 | 现状 | 适合 |
|---|---|---|---|
| **快照** | `world_state.json`、`story_threads.json`、`meta.json`、`workflow.json` | JSON 原子写，整份读写 | 字段少、读全量、要可 diff/可备份/可手改 |
| **流水** | `world_state.location_log`、`canon/events.jsonl`、`runs/*.jsonl` | 追加为主；`location_log` 内嵌 JSON（上限 2000），`events/runs` 是 JSONL | 按时间回放、单机少量查询 |

当前 `location_log` 的查询走 `WorldState.query_location_log(character, location, start, end, limit)`，
在 2000 条上限内线性过滤足够快；JSON 的好处是可直接看、可直接改、跟快照一起备份。

**什么时候该上 SQLite**：单项目流水超过约 1–2 万条，或需要频繁做「某角色在某地点某章区间」的
组合查询/分页/聚合，或未来要多进程同时写。届时把 `location_log` 迁到 `ledger.db`
（`chapter, character, action, location, from, ts` 建索引），`world_state.json` 只保留最近 N 条
供 UI 首屏；`canon/events.jsonl` 继续保持 append-only（哈希链语义不适合频繁更新）。

**RAG 不能替代结构化状态**：RAG 是模糊召回，适合「前文里剑灵怎么出场的」这类散文检索；
「角色现在在哪、当前目标是什么、伏笔是否已回收」必须走结构化字段精确读取。
两者是互补关系，不是替代关系。

## 原子写入（`read_md` / `write_md` / `write_json`）

```
write: 先写 .tmp → os.replace 原子改名
```

防崩溃丢数据。所有 md/txt/json 状态写入均走此路径（含 `meta.json` / `memory.json` / `world_state` / `reading_power` / `anti_patterns` / `rag_*.json` / `config.json`）。

## 核心 API（`project_io`）

| 函数 | 语义 |
|------|------|
| `chapter_filename(n, title)` | `1_第一章.txt` |
| `scan_chapters(dir)` | 按数字排序扫描章节 |
| `find_chapter_file(dir, n)` | 按序号定位文件 |
| `read_md / write_md / write_json` | 原子读写 |
| `load_workflow / save_workflow` | 工作流进度（合并写 + JSON 损坏容错） |
| `load_meta / save_meta` | 项目元信息（导出书名/作者来源） |
| `rename_chapter` / `safe_rename_chapter` | 改名（后者含冲突检测） |
| `validate_chapter_content` | 空/过短/只有标题校验 |
| `generate_toc` | 生成 `planning/目录.md` |
| `load_chapter_summaries(up_to, window)` | 加载概要（上下文组装用） |
| `latest_summary(dir)` | 最新剧情摘要（**按解析章号排序**，非文件名字典序） |
| `chapter_summary_path(dir, n, title)` | 概要路径 |
| `delete_project(dir)` | 删除项目；失败返回 `False`（不再静默吞掉） |

> 故事线台账不是 `project_io` 的职责：入口是 `core/story_threads.sync_story_threads(dir)`
> （解析四份规划稿 + 对账 memory/world_state），只读写 `story_threads.json`。

## 项目目录名（`safe_project_dirname`）

书名清洗为目录名：剔除 `\/:*?"<>|` 与控制符、首尾点空格、Windows 保留设备名（`CON`/`NUL`/…）加前缀 `_`、空名回退「未命名项目」。防 `..` 路径穿越与同名覆盖（冲突自动加 `_2` 后缀）。

## 应用级配置（`app_config.py`）

| 项 | 开发环境 | PyInstaller 打包后 |
|----|----------|-------------------|
| 用户数据 | `<项目根>/data/` | Windows `%APPDATA%/NovelWriter`；macOS `~/Library/Application Support/NovelWriter`；Linux `~/.local/share/novel-writer` |
| 用户配置 | `data/config.json`（chmod 600，含 API Key） | 同上 |
| 智能体配置 | `config/agents.json`（含 system_prompt） | 随包 |
| 智能体默认 | `config/default_agents.json`（重置用） | 随包 |
| 默认供应商 | `config/default_providers.json` | 随包 |
| 日志 | `logs/info.log` + `logs/error.log` | 用户数据目录下 `logs/` |

## 数据模型（`models/`）

| 模块 | 职责 |
|------|------|
| `project.py` | `Project` — 基于目录的存储门面 |
| `chapter.py` | `Chapter` — 章节文件 IO |
| `character.py` | `Character` |

## 边界与已知限制

- `storage/` 目录目前是抽象层占位（`__init__.py`），实际 IO 集中在 `project_io`。
- 章节改名需同步正文 heading + 细纲文件名，`safe_rename_chapter` 已封装，禁止绕过直改文件名。
- `chat.db` 默认不创建；只有 `config.json` 里 `save_chat_history=true` 才会落盘。
- 工作流**不读** `chat.db`；上下文里的“记忆”来自 `memory.json` / `summary/` / `world_state.json`（含 `locations` / `items_catalog` / `location_log` 地点流水；正典写入前会 compact 成 diff） / `canon/`，不是聊天记录。
- 打包后数据**不写可执行文件旁**（Program Files 无写权限）：`DATA_DIR` 走系统用户目录（见上表），`config/` 是随包只读资源，用户配置写在 `DATA_DIR/config.json`；`logs/` 在用户数据目录下运行时自动建。

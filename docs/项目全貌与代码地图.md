# 项目全貌与代码地图

> 性质：`参考`（人读导航，不参与算法口径裁决）
> 对应版本：工作区 `e293ea4` + 未提交改动（2026-10-18）
> 用途：30 分钟内建立「这个项目怎么跑、数据怎么流、改哪里」的完整心智模型

## 一句话

Novel Writer 是一个 **PySide6 桌面端 AI 长篇小说创作工作台**：用「多 Agent + 可组合工作流」把一次性的 LLM 对话，变成能连续写 100 章、且跨章不崩设定的生产流水线。它真正的护城河不是 UI，而是 `core/` 里的四件事：**分层上下文、外部记忆/世界状态、规则质检、断点续跑**。

```
main.py / python -m novel_writer
  └─ app.py: main()
       ├─ 预热 openai/httpx/anyio，绕开 shiboken 特性检查（macOS/打包环境防卡死）
       ├─ QApplication + 全局字体 + 禁滚轮改下拉框
       ├─ SplashScreen（STARTUP_STAGES 假进度，仅视觉）
       └─ MainWindow()
            ├─ _setup_ui()     三栏 QSplitter
            ├─ _setup_menu()   文件 / 模型与智能体 / 工作流 / 关于
            ├─ _init_llm()     读 data/config.json → LLMClient
            ├─ _init_agents()  读 config/agents.json → 7 个 BaseAgent
            └─ _setup_workflow() 连接工作流条信号
```

数据根目录由 `core/app_config.py` 决定：开发态是仓库 `data/`；打包后落到系统用户目录（macOS `~/Library/Application Support/NovelWriter`）。

## 3. 架构分层与依赖规则

```
ui/  ──────────────►  core/ + models/
（Qt、控件、线程）      （纯 Python，可无 GUI 测试）
        designsystem/  tokens.py（色值唯一来源）
```

硬约束由 `tests/test_arch_guard.py` 守护：

1. `core/`、`models/`、`storage/` 不得 import PySide6/PyQt/shiboken；
2. `core/` 不得 import `ui/`；
3. `ui/` 根目录只允许 `main_window.py`，功能页必须进子包。

`MainWindow` 只有 ~144 行，行为拆到 `ui/app_shell/` 六个 Mixin：

| Mixin | 职责 |
|---|---|
| `theme_mixin` | 主题/菜单/Toast/关于 |
| `llm_mixin` | 供应商 → LLMClient、Agent 实例化（支持每个 Agent 独立模型） |
| `project_mixin` | 新建/打开/保存、章节增删改、导出 |
| `chat_mixin` | 自由对话、流式渲染、上下文组装入口 |
| `settings_mixin` | 设置对话框 |
| `workflow_mixin` | 工作流启动/续跑/进度/停止/编辑器刷新 |

> 正文流式：MiMo/DeepSeek/Qwen 的 stream 会先推 reasoning、后推 content；正文步给 8192 token 预算，避免思考吃完配额导致空正文。

## 4. UI 结构与线程模型

三栏 `QSplitter`（`ui/main_window.py`，初始 240/680/480）：

```
Sidebar（200–320px）      EditorPanel（弹性）           AgentPanel（≥340px）
├ 新建/打开项目            ├ 正文编辑（限宽 920px）        ├ Agent 状态条（104/182px）
├ 章节树                   ├ 字数统计                     ├ WorkflowMiniBar（两段进度）
└ 项目字数统计             └ 规划：左列表 + 右编辑器       ├ Agent 信息 + 快捷动作
                                                          ├ 聊天滚动区（流式气泡）
                                                          └ 输入区（固定 132px）
```

- **规划文档 9 个**：立意、大纲、章节细纲、人物设定、世界观、时间线、主线、支线、伏笔。顶部有「正文 / 规划 / 世界」三个标签，世界页左侧菜单含人物/物品/地点，规划页左侧列表切换，内容懒加载，编辑 1.5s 防抖自动保存（`editor_panel.py`）。
- **专注模式**：`Ctrl+Shift+F` 隐藏左右栏，只留正文。
- **Agent 线程**：`AgentWorker(QThread)` 自建 event loop 调 `agent.stream_run`，`chunk_received(kind,text)` 逐片回 UI，`thinking` 灰字、正文常规色。所有 worker 挂在模块级 `_ALIVE_WORKERS` 强引用，等内建 `finished` 再释放，避免「QThread: Destroyed while running」崩溃。
- **工作流线程**：`WorkflowThread(QThread)` 在自身 loop 跑 `WorkflowRunner.run`，把 runner 的 3 个回调转成 Qt 信号（step_started/finished/error/progress/log/done/stopped）。停止 = 置 `_stop` + `task.cancel`，秒级中断 LLM 请求。
- **主题**：`designsystem/tokens.py` 四套色板（深夜墨/晨雾白/远山蓝/苍山绿）+ 自定义，`ui/common/styles.py` 只消费 token 生成 QSS；Agent 状态条/表单/对话框都跟随主题。
- **i18n**：`locales.py` 字典 + `t(key)`，中/英切换。

关键 IO 约定（`core/project_io.py`）：

- **原子写**：所有 `write_md/write_json` 先写 `.tmp` 再 `Path.replace`；`config.json` 额外 fsync + chmod 600。
- **章节正则**：`^(?!.*\.bak\.txt$)(\d+)_(.+)\.txt$` —— 显式排除备份，避免润色/上下文/RAG 读错文件。
- **目录名清洗**：`safe_project_dirname` 处理非法字符、Windows 保留名、首尾点空格、空名。
- **进度合并写**：`save_workflow` 先读旧 JSON 再 update，防止存进度时抹掉工作流定义。

## 6. 工作流引擎（`core/workflow/`）

### 6.1 五种模式

| 模式 | 组成 |
|---|---|
| `NEW_BOOK` | 9 个规划步 + `fix_titles` + 15 个循环步 |
| `NEW_BOOK_PLANNING` | 仅 9 个规划步 |
| `CONTINUE` | `fix_titles` + 循环步，`_start_chapter` 指定起点 |
| `FILL_GAPS` | 仅一个 `chapter` 步 + `project["_gaps"]` 缺章列表 |
| `VALIDATE` | `fix_titles → toc → review → proofread` |

模板是**单一来源**组合：`DEFAULT = _PLANNING_STEPS + fix_titles + _CYCLE_STEPS`，避免四份复制漂移。

### 6.2 循环步骤与触发语义

章前：`inspiration`（每 3 章）、`sim`（每章）。
章后：`chapter_summary`、`world_state_update`、`toc`（每章）；`polish`（每 2 章）；`proofread`、`quality_check`（每章）；`summary` 与四个 `update_*`（每 5 章）；`review`（最后）。

- `every` 的判定基准是**章号**（`n % every == 0`），所以第 1、2 章不会触发 inspiration。
- `repeat` 由 `build_workflow` 设成目标总章数（不是「剩余章数」）。
- 每轮循环开始会清空**全部 Agent 历史**：跨章连贯性由上下文组装负责，历史累积几十章会撑爆上下文；规划链的历史只用于规划阶段。

### 6.3 执行语义

| 特性 | 实现 |
|---|---|
| 断点恢复 | `workflow.json` 存每步 done / 循环步 `{current,total}`；恢复从 `current+1` 章继续 |
| 智能跳过 | done 且产出文件存在非空才跳过；文件被删会自动重跑 |
| 单章失败 | 记 `_errors` 后跳下一章，不终止整跑 |
| 缺 Agent | `WorkflowError` fail-fast（配置错误重试无意义） |
| 定时步骤失败 | 标 `"error"`，恢复时重试 |
| 并发 | 连续 `parallel_ok` 步骤 `asyncio.gather`，按发起时固定列表 zip |
| Token | 累计标准步骤的 `usage` 到 `progress["_usage"]` |

### 6.4 内置步骤（9 个，`BUILTIN_STEP_HANDLERS`）

`toc`（纯规则）、`fix_titles`（LLM JSON 改名）、`chapter_summary`（LLM 概要）、`world_state_update`（LLM JSON → 快照）、`quality_check`（纯规则）、`proofread`（逐章或全书分批）、`review`（全书分批 + 聚合）、`chapter_outline`（分批 15 章）、`update_chapter_outline`（每 5 章修订）。

内置步骤**绕过** `ContextBuilder` 和统一 LLM 治理：自己拼 prompt、自己调 `agent.run`，因此不参与上下文预算、token 统计、`step.thinking` 控制。

## 7. 一章的完整生命周期（最重要的一条链路）

```
① 章前 inspiration / sim
② chapter：ContextBuilder.build() → prompt → LLM → 校验 → 写 chapters/{n}_{title}.txt
         （写前备份 .bak.txt；已有内容则跳过不覆写）
③ 章后 chapter_summary → world_state_update → toc
         → polish（每 2 章，就地覆写正文）
         → proofread / quality_check
         → summary（每 5 章）
         → update_outline / update_characters / update_foreshadow / update_chapter_outline（每 5 章）
④ sediment（全部章后步骤跑完、读最终落盘正文）
         ├ LLM 语义沉淀：状态/伏笔开关/读者承诺/关系/世界规则
         ├ 正则兜底：状态变化/伏笔抽取/伏笔自动回收
         ├ chapter_tracker 四维：资源/情感/信息边界/支线
         ├ memory.compact + save
         ├ anti_patterns.clear_resolved（10 章过期清理）
         └ reading_power.analyze + record
⑤ 下一章 build()：把 ②④ 的产物按「头/中/尾」重新注入
```

> 关键设计：**草稿不是正典**。沉淀放在润色之后、读最终文件，保证「写进记忆的」就是读者看到的。

## 8. 分层上下文组装（`core/workflow/context.py`）

### 8.1 四层

| Tier | 注入内容 | 典型步骤 |
|---|---|---|
| GLOBAL | 项目元信息 | toc、fix_titles、chapter_summary、ideation、outline、proofread、quality_check |
| WORLD | + 世界简报、角色状态、角色约束、规划文档 RAG | characters/world/timeline/main_plot/sub_plot/foreshadow/chapter_outline/sim/world_state_update |
| NARRATIVE | + 剧情摘要、伏笔、反模式、追读力 | inspiration/polish/review/summary/update_* |
| WORKING | + 上章回顾、推演、近 5 章概要、近 2 章全文、章节 RAG | chapter（未映射步骤默认落此层） |

### 8.2 注意力布局

- **头**（高注意力）：项目元信息 → 角色锚定硬约束 → 活性记忆卡（只取本章出场实体）。
- **中**（可压缩）：世界设定 → 合并角色状态 → 关系/世界规则 → 本章大纲 + 本章细纲 → 规划文档 BM25 top-5 → 滚动摘要 → 工作记忆。
- **尾**（高注意力）：未解伏笔（动态紧急度排序，超期标「优先回收」）→ 近 8 章已回收 → 读者承诺 → 信息边界 → 上章承接点 → 反模式 → 追读力指导。

### 8.3 预算与压缩

- 估算：`中文字 × 1.5 + 英文词 × 1.3`；默认预算 **48,000 tokens**（UI `max_context_tokens` 可调）。
- 两级压缩：
  1. **块内缩量**：RAG 留 2 条 ×120 字；旧章全文除最新外截 600；规划截 300；推演截 600。
  2. **整段丢弃**：`rag → chapter_full → planning → sim → summary`。
- `other` 类（元信息、角色约束、活性记忆卡、剧情摘要）**永不裁剪**——宁可略超预算也不丢硬约束，这是刻意取舍，也是潜在超限点。

### 8.4 检索

- 章节 RAG：BM25（`k1=1.5, b=0.75`），中文 bigram+unigram 分词，按 `\n\n` 分块、<20 字丢弃；只索引到 `n-2`，最近两章走全文。
- 规划文档 RAG：`人物设定.md` 全文注入（角色约束需要完整信息），其余文档 top-5 ×300 字。
- 可选语义检索：配置 embedding 后 `rag_vectors.json` 持久化，内容指纹键防旧向量；失败静默回退 BM25。

## 9. 记忆、状态与质量

| 子系统 | 文件 | 定位 |
|---|---|---|
| 长期记忆 | `memory.json` | **11 桶流水**：character_state / story_facts / world_rules / timeline / open_loops / reader_promises / relationships / resources / emotional_arcs / info_boundary / subplots。同键新值覆盖、旧值 `outdated` 审计 |
| 世界状态 | `world_state.json` | **当前快照**：world / characters / items_catalog / timeline。LLM 增量 JSON → 深度合并 |
| 四维追踪 | 写 memory | 资源账本 / 情感弧线 / 信息边界 / 支线进度，正则抽取，维度级隔离 |
| 反模式 | `anti_patterns.json` | 审稿 AI 味 → 禁忌库 → 写作约束；空库回退 7 条默认 |
| 追读力 | `reading_power.json` | 5 类钩子 × 强度、8 类爽点、7 类微兑现（检测 4 桶）、阅读债务；滑窗生成下一章指导 |
| 质量检查 | 无（写报告） | 10 维规则加权：对话/节奏各 0.15，其余 0.05–0.1；3000–4000 字满分 |

> 分工一句话：**world_state 存快照，memory 存流水，chapter_tracker 补四维，reading_power 管读者体验，quality_checker 做体检**。

## 10. LLM 与 Agent

- `config/agents.json`：7 个 Agent（主编/策划/写手/校对/审核/灵感/润色），每个可独立 `model`、`temperature`、`max_tokens`、`thinking`、`skills`。工作流用 `needs` 技能名匹配；同技能多 Agent 轮换默认关闭（会打断规划链历史）。
- `core/llm/client.py`：统一 OpenAI 兼容协议（`api_key + base_url + model`），懒加载 SDK、按 event loop 重建 httpx、`certifi` 证书、300s 超时、3 次指数退避、429 冷却、流式已产出不重试。
- 思考模式：`off/on/auto`，按模型方言（qwen/glm/deepseek/kimi/mimo）映射 `extra_body`；工具类步骤强制 off。
- 其余三个驱动（Claude 原生 / Ollama / OpenAICompat）**当前无装配点**，只有 `LLMClient` 在用；这是历史兼容层，不是死代码但也没被验证。

## 12. 风险清单（按优先级）

> 以下均为**当前工作区**可复现的问题，不是泛泛而谈。

### ✅ P0-1 — 切换/新建项目会清空上一个项目「当前打开的那一章」（已修复）

这是当前最危险的数据丢失路径，已在本机 offscreen 复现：

1. `_load_project_from_dir` 先把 `self.project` 换成新项目，再调用 `editor.clear()`（`project_mixin.py:108-120`）；`_new_project` 同样（`project_mixin.py:86`）。
2. `editor.clear()` 里的 `content_edit.clear()` 没有 `blockSignals`（`editor_panel.py:303-306`）。
3. 清空触发 `textChanged → _on_text_changed → content_changed`（`editor_panel.py:123,316-318`）。
4. `_on_content_changed` 从 `editor._current_chapter` 取章节——此时它仍指向**上一个项目**的 Chapter（`project_mixin.py:147-155`），于是 `chapter.content = ""`，`Chapter.content` setter 立即原子写盘（`models/chapter.py:56-58`）。

结果：用户切换到新项目/新建项目的一瞬间，旧项目最后打开的那一章被写成空文件。复现输出：`after clear -> chapter content len: 0, writes: [0]`。

修复：新增 `EditorPanel.detach_chapter()`（置空 `_current_chapter` + `blockSignals` 清空），`clear()` 与新建/打开项目前都调用；回归测试 `tests/test_editor_safety.py` 3 例。

### ✅ P0-2 — 章节细纲修订会被截断，且覆盖整份文件（已修复）

`update_chapter_outline` 要求 LLM「输出完整细纲（第 1 章到第 N 章）」，然后**整文件覆盖**；但策划 Agent 的 `max_tokens=4096`，而 100 章细纲实测 25,005 字符（约 1.3 万字）。一次输出上限远小于全文，第 5/10/15… 章各修订一次，文件会逐步退化为前二三十章。

- 证据：`builtin_steps.py:511-556`（覆盖写）、`prompts.py:295`（要求完整）、`config/agents.json`（planner 4096）、`agents/base.py:109`（默认取 config）
- 建议：只请求 `n+1..n+20` 的增量，按章 splice；或显式 `max_tokens=32k` + 分批；写前校验 `## 第` 数量，缺失则保留旧文件并告警。补一条「LLM 返回短文本时旧文件不被覆盖」的回归测试。

### ✅ P1 — 反模式回灌是死代码，禁忌库永远为空（已修复）

`review` 已是内置步骤，`runner._run_single` 在内置分发后立即 `return`，因此 `runner.py:391-395` 的 `add_from_review` 永远不可达。实际效果：`anti_patterns.json` 从不自动写入，写作上下文只注入 7 条默认禁忌。

- 证据：`runner.py:313-316`、`runner.py:391-395`、`builtin_steps.py:342`
- 修复：`_run_review` 落盘后直接 `add_from_review`；`review_panel` 同样入库。

### ✅ P1 — 断点恢复会丢「当前章的章后步骤 + 沉淀」（已修复）

循环里先写 `progress["chapter"] = {current:n}`，再跑章后 periodic 和 sediment。若在两者之间停止/崩溃，恢复从 `n+1` 开始，第 n 章的 polish/proofread/summary/world_state/sediment 永久跳过。`sediment_n` 有独立键，但恢复逻辑不会回头补。

- 证据：`runner.py:224-234`、`runner.py:190-195`
- 修复：`progress[step.id]` 移到章后 periodic + sediment 之后；停止时 break 且不推进；回归测试 `test_stop_during_post_step_does_not_advance_current`。

### ✅ P1 — 写失败仍推进进度（假成功）（已修复）

章节内容校验失败/润色过短/空报告时，`_write_output` 返回 `False`，`_run_single` 直接 `return`，外层仍写 `current=n`。恢复时该章被视为已完成，不会重试。

- 证据：`runner.py:384-389`、`runner.py:432-439`、`runner.py:224`
- 修复：正文校验失败抛 `ChapterWriteRejected`，循环记录 `_errors` 但不写 current；其它报告类写失败仍只跳过。

### ✅ P1 — 已有章节的项目无法生成章节细纲（已修复）

- `NEW_BOOK` / `NEW_BOOK_PLANNING` 在有章节时被 UI 拒绝（`workflow_mixin.py:78-88`）。
- `CONTINUE` 模板没有 `chapter_outline`（`definition.py:149-153`）。
- `update_chapter_outline` 发现文件不存在时直接 return（`builtin_steps.py:516-519`）。

修复：CONTINUE 模板加入 optional 的 `chapter_outline`，缺失时生成、已有则智能跳过。

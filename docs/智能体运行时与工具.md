# 智能体运行时与工具（DSH 借鉴）

> 引擎：`src/novel_writer/core/agents/{loop,tools}.py`、`src/novel_writer/core/skills.py`、`src/novel_writer/core/workflow/journal.py`
> 参考：deepseek-harness 的 agent loop / tool pipeline / skill registry / workflow fan-out 设计
> 性质：`参考`（设计说明，改动需同步代码与测试）

## 一句话总结

把「一次性把全部设定塞给模型」改成 **模型按需拉取事实**：写作 Agent 可以在受限轮数内调用只读工具（规划/前文/记忆/世界状态/伏笔/技能包），工作流则获得 **声明式依赖、重试/超时、并行会审、JSONL 运行日志** 这四件长跑基础设施。

## 1. 为什么借 DSH 的这几块

| DSH 设计 | 本项目的落点 | 解决的问题 |
|---|---|---|
| Agent loop：请求 → 工具 → 再请求，轮数/预算受限 | `AgentLoop` + `BaseAgent.run_with_tools` | 固定上下文会漏细节；模型需要「查一下再说」 |
| 只读工具流水线 | `NovelToolkit` / `ToolRegistry` | 防止模型改稿；工具结果可截断、可审计 |
| Skill registry：目录 + 按需加载正文 | `SkillRegistry` + `use_skill` 工具 | 写作工艺指南不再全量注入，按需取用 |
| Workflow `parallel()` / `pipeline()` / phase / log | `review_panel` 三视角并行会审；`RunJournal` | 审稿从「一个 Agent 一次说完」变成「多视角扇出 + 主编收敛」 |
| 会话/轨迹日志 | `runs/*.jsonl` | 长跑排障、成本审计、断点复盘 |
| 工具使用预算与失败回退 | `max_rounds` / `max_calls_per_round` / LLM 层降级 | 不让工具循环无限烧 token，也不因模型不支持 tools 而失败 |

**刻意没做的**：没有引入 DSH 的 PTC/JS 沙箱、没有给模型写文件/执行命令的工具、没有做多进程 subagent。对小说写作来说，越权写稿和任意执行的收益远小于风险；先把「只读检索」这一层做稳。

## 2. 工具循环（`AgentLoop`）

```
messages = system_prompt + context(含工具说明) + history + user
for round in 0..max_rounds:
    resp = llm.chat(messages, tools=schemas if round < max_rounds else None)
    if 没有 tool_calls 或 已是最后一轮: 返回 resp
    messages += assistant(tool_calls)
    for call in 本轮前 max_calls_per_round 个:
        result = tool_registry.execute(name, args)   # 异常转文本，不中断
        messages += tool(result, tool_call_id)
```

口径：

| 参数 | 默认 | 说明 |
|---|---|---|
| `WorkflowStep.tool_rounds` | `2` | 最多几轮工具调用；0 = 不给工具 |
| `AgentLoop.max_calls_per_round` | `4` | 每轮最多执行几个调用（多余调用被丢弃，避免 tool_call 无响应） |
| `ToolRegistry.max_result_chars` | `8000` | 单条工具结果上限，超出截断 |
| `enable_tools` | `True`（`config.json`） | 总开关；关闭后所有步骤退回纯文本 |

失败语义：

- 工具不存在/参数错/执行异常 → 返回 `ERROR: ...` 文本，模型可自行修正或放弃；
- 模型/网关不支持 `tools` → `LLMClient` 自动去掉 `tools` 重试一次（`_is_invalid_request`）；
- 工具预算耗尽 → 最后一轮不传 `tools`，强制模型基于已有信息收束；
- `keep_history=False` 时工具往返不写入 Agent 历史，只写最终答案。

## 3. 只读工具清单（`NovelToolkit`）

| 工具 | 参数 | 返回 | 典型用途 |
|---|---|---|---|
| `read_planning` | `doc` | 规划文档全文（≤8000 字） | 写前核对人物/世界观/伏笔 |
| `read_chapter` | `number` | 指定章正文（≤8000 字） | 核对前文原句、伤势、物品 |
| `search_chapters` | `query`, `top_k` | RAG top-k 片段 + 出处 | 忘了某设定在哪章出现 |
| `get_world_state` | `entity?` | 角色/物品/地点/时间线快照 | 查当前境界、背包、位置 |
| `get_memory` | `bucket?`, `subject?` | 活跃记忆项（≤20 条） | 查关系、承诺、信息边界 |
| `get_open_loops` | — | 未解伏笔 + 动态紧急度 | 决定本章回收/延续哪个伏笔 |
| `list_chapters` | — | 章号/标题/字数/有无概要 | 规划检索范围 |
| `list_skills` | — | 技能目录 | 让模型知道有哪些工艺包 |
| `use_skill` | `name` | 技能正文（≤6000 字） | 加载开篇/对话/战斗/情感/悬念/连续性指南 |

安全边界：

- `read_planning` 只接受 `planning/` 下 9 个固定文件名 + `目录.md`，路径穿越直接拒绝；
- 没有写文件、改正文、删章节、调用外部命令的工具；
- 所有读取都走 `project_io`，UTF-8 + 只读；结果统一截断。

## 4. 技能包（`SkillRegistry`）

目录优先级（后者覆盖前者）：

```
项目 skills/  >  config/skills/  >  src/novel_writer/skills/（内置）
```

内置 6 个：`chapter-craft`（章节工艺）、`dialogue`（对话）、`battle`（战斗）、`emotion`（情感）、`suspense`（悬念/伏笔）、`continuity`（连续性自检）。

自定义格式（`skills/my-skill.md`）：

```markdown
---
name: my-skill
description: 一句话说明
when_to_use: 什么场景加载
---
正文：可执行的写作规则/检查清单
```

两种使用方式：

1. **模型主动加载**：Agent 调 `list_skills` → `use_skill("chapter-craft")`；
2. **步骤强制注入**：`WorkflowStep.skills = ["continuity"]`，runner 在组装上下文后追加技能正文（适合必须遵守的自检项）。

## 5. 工作流增强

### 5.1 新步骤字段（`WorkflowStep`）

| 字段 | 默认 | 语义 |
|---|---|---|
| `depends_on` | `[]` | 声明后启用 DAG：拓扑分层，同层并发、层间串行；未知依赖/环直接报错 |
| `retry` | `0` | 失败重试次数（不含首次）；配置错误、写盘被拒不重试 |
| `retry_delay` | `2.0` | 指数退避基数：2s、4s、8s… |
| `timeout` | `0` | 单步超时秒数（`asyncio.wait_for`），0=不限 |
| `tools` | `[]` | 本步工具白名单；空=不启用工具 |
| `tool_rounds` | `2` | 工具轮数 |
| `skills` | `[]` | 强制注入上下文的技能包 |
| `phase` | `""` | 日志/进度分组名 |

未声明任何 `depends_on` 时保持原语义（连续 `parallel_ok` 并发），不会改变既有模板行为。

### 5.2 多视角会审 `review_panel`（每 10 章）

```
最近 3 章正文
   ├── 剧情逻辑 reviewer ─┐
   ├── 人物一致性 reviewer ├─→ 主编聚合 → review/会审报告_第a-b章.md
   └── 节奏爽点 reviewer ─┘
```

- 三个视角 `asyncio.gather` 并行（DSH `parallel()`），互不共享历史；
- 主编做 fan-in，去重后输出「必须修 / 建议修 / 可保留」；
- 报告同时喂给 `AntiPatternTracker`，形成审稿 → 禁忌库闭环；
- 单视角失败只跳过该视角，不阻断整步。

### 5.3 运行日志 `runs/*.jsonl`

每次 run 在项目下写一份 append-only JSONL：

```
run_start → step_start → tool_call/tool_result → step_end
          → step_retry → step_error → story_track → run_end
```

字段含 `ts`、`step`、`n`、`duration_s`、`phase`、`usage`、`error`。不落正文，文件小、可 `jq` 直接分析；UI 工作流日志会打印日志路径。

### 5.4 用量与断点

- **用量**：`BaseAgent.usage_sink` 由 runner 注入，内置步骤（概要/世界状态/校对/审核/沉淀/细纲）与工具循环全部计入 `total_usage`；原先只有标准步骤计数。
- **断点**：`progress["chapter"] = {current:n}` 移到章后步骤 + 沉淀全部完成之后；中途停止不会再把「章后链路没跑完」的章节标成完成。
- **写失败**：章节内容校验失败抛 `ChapterWriteRejected`，记录错误但不推进 current，恢复时会重试该章。

## 6. 配置与开关

`data/config.json`：

```json
{"enable_tools": true}
```

关闭后所有步骤退回纯文本（仍保留技能注入）。单个步骤要禁用工具，把模板里的 `tools` 去掉即可。

## 7. 边界与已知限制

- 工具只读，不能替代「改稿」；润色/替换仍由工作流写盘。
- 工具调用会增加 1–2 次请求；对不支持 tools 的模型，第一次会多一次 400 重试（自动降级）。
- `search_chapters` 首次会建/载入 RAG 索引，长书第一调用可能慢；之后走缓存。
- `review_panel` 每 10 章 4 次调用，成本较高；不需要可在模板里删掉或改 `every`。
- DAG 只在 `every == 0` 的普通步骤上生效；`repeat`/周期步骤仍按章节循环执行。
- 技能正文仍是提示词，不保证模型 100% 遵守；关键约束（不换主角、不改名）仍在硬约束块里。

## 8. 与角色层的关系

工具循环服务的是**作者侧 Agent**（写手/审核/润色）。角色 POV Agent 不走这套工具：它只有 `CharacterView`，禁止读规划/全局状态。两者边界见 [角色生命周期与POV推演.md](角色生命周期与POV推演.md)。

# 短剧跨章分集

「短剧 → 智能分集」提供“生成下一集”与“持续分集”两种范围。旧的逐章转剧本入口保留。

每轮从未使用的素材中读取最多 5 章完整正文，单轮最多 50,000 字符；超出预算时缩小完整章节窗口，不截断原文。模型先输出本集标题、目标、钩子、剧情节拍和来源章节，再把选定素材交给编剧生成场次剧本。

例如先读第 1–5 章，规划选取第 1–4 章生成第 1 集：第 5 章保持待用，下轮补读第 6–9 章。模型只能选取阅读窗口的连续前缀，不能跳章或重复消费；只有剧本成功保存后才确认来源映射。素材不足时可标记等待后续正文，不强行成集。

## 数据与恢复

- `drama/episodes.json`：每集的 `source_chapters`、`source_hashes` 与 `adaptation_plan`；这是素材是否已使用的权威来源，兼容旧 `source_chapter`。
- `drama/adaptation.json`：待用章节、最近阅读窗口和顺延原因，是可重建的状态快照。
- `drama/episodes/epNNN.md`：剧本；写入成功才提交来源元数据。元数据写入失败则回滚主剧本，生成稿保留为 `.pending.md`。
- 恢复时从来源映射重新计算未用素材，避免因停止或旧快照重复生成。旧项目已经关联的章节也算已用。
- 已改编源文的指纹变化、已用素材中间出现缺口时，停止自动续接并提示复核，防止新旧剧情混用或次序颠倒。

剧本页显示来源章节；顶部概览显示待用章节，悬浮可查看顺延原因。小说正文不被改写；逐章生成不能覆盖已经合并多章的剧集。

## 边界

当前使用完整章节作为素材单位，支持多章合一集；不支持将同一章拆到多集。来源映射代表素材已经过该集改编，不意味着每段原文都逐字保留。规划与编剧各一次模型调用，规划格式不合法可修复一次。真实戏剧质量仍需人工审阅。

核心服务：`core/drama_adaptation.py`；存储：`core/drama.py`；Qt Worker 只负责模型调用适配、信号与取消。

# 短剧跨章分集

「短剧 → 智能分集」提供“生成下一集”与“持续分集”两种范围。旧的逐章转剧本入口保留。

每轮从未使用的素材中读取最多 5 章，单轮原始素材最多 50,000 字符（`MAX_SOURCE_CHARS`，超出就缩小窗口，不会把一章拆开）。**送进模型的是逐章切片，不是全文**：每章按冲突密度选场景块，窗口总量再压到 9,000 字符以内。模型先输出本集标题、目标、钩子、剧情节拍和来源章节，再把选定素材的切片交给编剧生成场次剧本。

例如先读第 1–5 章，规划选取第 1–4 章生成第 1 集：第 5 章保持待用，下轮补读第 6–9 章。模型只能选取阅读窗口的连续前缀，不能跳章或重复消费；只有剧本成功保存后才确认来源映射。素材不足时可标记等待后续正文，不强行成集。

## 上下文切片（`core/drama_context.py`）

短剧最怕「把整本塞进去」：上下文一长，模型就开始平均用力，冲突被铺陈稀释，成本还成倍涨。所以按经验规则切片：

| 规则 | 做法 |
|---|---|
| 预算内不切 | 文本没超预算就原样送，不做无谓的信息损失 |
| 按场景切 | 超预算时复用 RAG 的场景分块（`rag_chunking.chunk_chapter`），一场戏不会被拦腰截断 |
| 冲突密度优先 | 冲突/反转/决定类词、对白行、出场人物越多得分越高；铺陈、抒情、设定说明先被丢 |
| 首尾必留 | 开场块和最后一块先占预算（承载入戏与集尾钩子） |
| 原序拼接 | 选中的块按原文顺序还原，块间标「（略）」，提示模型不要补写被略过的剧情 |

预算（字符）：分集策划单章 2,000 / 窗口 9,000；单集剧本原文 12,000；改编圣经 6,000、单份规划文档 2,600；分镜剧本 12,000；上一集结尾 900。

其它切片：

- **改编圣经**按 Markdown 小节选：优先「红线 / 规则 / 节奏 / 钩子 / 视觉锚点」相关小节，其余按预算截断。
- **人物档案**只留本章/本集出场的人（角色名从正文匹配），一个都没匹配上才退回按预算切片。
- **分镜**超预算时压动作描述、保全部 `## 场次` 标题与台词，镜头表不会缺场。
- **前情**只回看最近 3 集的「集名 / 目标 / 钩子」+ 上一集结尾 900 字，不整段回读。

Worker 每次调用会往日志里写一行切片账单（原文多少字 → 送入多少字），便于核对成本和是否漏料。

## 数据与恢复

- `drama/episodes.json`：每集的 `source_chapters`、`source_hashes` 与 `adaptation_plan`；这是素材是否已使用的权威来源，兼容旧 `source_chapter`。
- `drama/adaptation.json`：待用章节、最近阅读窗口和顺延原因，是可重建的状态快照。
- `drama/episodes/epNNN.md`：剧本；写入成功才提交来源元数据。元数据写入失败则回滚主剧本，生成稿保留为 `.pending.md`。
- 恢复时从来源映射重新计算未用素材，避免因停止或旧快照重复生成。旧项目已经关联的章节也算已用。
- 已改编源文的指纹变化、已用素材中间出现缺口时，停止自动续接并提示复核，防止新旧剧情混用或次序颠倒。

剧本页显示来源章节；顶部概览显示待用章节，悬浮可查看顺延原因。小说正文不被改写；逐章生成不能覆盖已经合并多章的剧集。

## 边界

当前**素材单位**仍是完整章节，支持多章合一集；不支持将同一章拆到多集（但提示词内部会按场景切片，标「（略）」≠ 素材未使用）。来源映射代表素材已经过该集改编，不意味着每段原文都逐字保留。规划与编剧各一次模型调用，规划格式不合法可修复一次。真实戏剧质量仍需人工审阅。

核心服务：`core/drama_adaptation.py`（分集/交接）、`core/drama_context.py`（切片与预算）；存储：`core/drama.py`；Qt Worker 只负责模型调用适配、信号与取消。

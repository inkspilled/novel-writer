# 工作流引擎算法

> 引擎：`src/novel_writer/core/workflow/`（`definition.py` / `runner.py` / `builtin_steps.py` / `constants.py`）
> 调用点：UI `workflow_panel.py`（WorkflowThread 后台执行）、`workflow_bar.py`（进度）
> 测试：`tests/test_workflow.py`、`tests/test_workflow_package.py`

## 一句话总结

可组合的工作流引擎：五种模式由**共享步骤列表**拼装；步骤支持 `every` 定时触发、`repeat` 循环、断点恢复、智能跳过；特殊步骤走 `BUILTIN_STEP_HANDLERS` 注册表分发，不走标准 LLM 路径。

## 五种模式（`WorkflowMode`）

| 模式 | id | 步骤组合 | 用途 |
|------|----|----------|------|
| 新书全流程 | `new_book` | 规划 + fix_titles + 逐章循环 | 从立意到审校 |
| 新书立意 | `new_book_planning` | 仅规划 | 只生成规划文档 |
| 续写 | `continue` | fix_titles + 逐章循环 | 从已有章节继续 |
| 查漏补缺 | `fill_gaps` | 仅 `chapter` 步骤（`_gaps` 缺章列表） | 补写缺失章节 |
| 校验 | `validate` | 校验小步骤集 | 审核+校对已有章节 |

模板由单一来源组合，避免四份互相复制：

```
DEFAULT   = _PLANNING_CORE_STEPS + [_CHAPTER_OUTLINE_PRE, _FIX_TITLES_STEP] + _CYCLE_STEPS
CONTINUE  = [_FIX_TITLES_STEP, _CHAPTER_OUTLINE_PRE] + _CYCLE_STEPS
PLANNING  = _PLANNING_STEPS（含 chapter_outline）
VALIDATE  = 校验专用小步骤集
```

## 步骤数据结构

```python
@dataclass
class WorkflowStep:
    id: str                    # 步骤 id（也是内置处理器注册键）
    needs: str                 # 需要的技能名（Agent 匹配用）
    prompt: str                # 指令模板，支持 {变量} 插值
    input_files: list[str]     # 输入文件（支持通配符 / prev_chapters）
    output: str                # 输出路径，支持 {n} 占位
    repeat: int = 0            # 循环次数（0=不循环）
    every: int = 0             # 每隔 N 章执行一次（0=每章）
    optional: bool = False     # 找不到 Agent 时跳过
    update_planning: bool = False  # 强制覆盖 planning/（反哺步骤）
    depends_on: list[str] = [] # 声明后启用 DAG（拓扑分层，同层并发）
    retry: int = 0             # 失败重试次数（指数退避）
    retry_delay: float = 2.0   # 退避基数
    timeout: float = 0.0       # 单步超时秒数，0=不限
    tools: list[str] = []      # 只读工具白名单（见智能体运行时文档）
    tool_rounds: int = 2       # 工具循环轮数
    skills: list[str] = []     # 强制注入上下文的技能包
    phase: str = ""            # 日志/进度分组
```

## 逐章循环步骤表（`_CYCLE_STEPS`）

| id | 技能 | every | 备注 |
|----|------|-------|------|
| `inspiration` | 灵感激发 | 3 | 产出 3 个转折方向 |
| `sim` | 角色推演 | 1 | **作者侧**全知预演，输出给写手 |
| `chapter` | 正文写作 | 1 | 主步骤 |
| `character_panel` | 剧情审查 | 1 | **内置**，仅 auto_sim 角色：并行多 POV 提案 + 场景 brief + 导演裁决 |
| `chapter_summary` | — | 1 | **内置**（LLM 生成概要） |
| `world_state_update` | — | 1 | **内置**（LLM JSON → 快照） |
| `toc` | — | 1 | **内置** |
| `polish` | 润色 | 2 | **减法润色**：去形容词/成语/比喻/凑字词、拆长句，不改剧情；就地覆盖正文 |
| `percept_extract` | 剧情审查 | 1 | **内置**，正文 → CanonEvent（observable/hidden/known_by），幂等 |
| `seal_chapter` | — | 1 | **内置**，可选 `seal_chapters`；章节摘要入正典，后续禁止覆写 |
| `offscreen_tick` | 剧情审查 | 5 | **内置**，批量推进离场角色（1 次调用/批），可关 |
| `proofread` | 错别字检查 | 1 | 输出 `review/校对报告_第{n}章.md` |
| `summary` | 剧情摘要 | 5 | 输出 `summary/第1-{n}章摘要.md` |
| `update_outline` | 故事结构 | **5** | `update_planning=True` |
| `update_characters` | 人物设定 | **5** | `update_planning=True` |
| `update_foreshadow` | 伏笔设计 | **5** | `update_planning=True` |
| `update_chapter_outline` | 故事结构 | **5** | **内置**，只修订未来 10 章并拼接，绝不整书覆盖 |
| `review_panel` | 剧情审查 | **10** | **内置**，三视角并行会审 + 主编聚合，输出 `review/会审报告_第a-b章.md` |
| `quality_check` | — | 1 | **内置**，见[质量检查算法](质量检查算法.md) |
| `review` | 剧情审查 | — | 全书审校（循环末） |

> 表中的章前/章后步骤混排展示；实际触发时机以 `constants.PRE_CHAPTER_PERIODIC_IDS` /
> `POST_CHAPTER_PERIODIC_IDS` 为准：章前 `inspiration` / `sim` / `character_panel`，
> 其余周期步骤章后执行。

### 双推演：author_sim 与 pov_sim

- `sim`（author_sim）：作者/导演视角，允许读大纲、全局状态、伏笔，产出给写手；
- `pov_sim`：角色视角，只给 `CharacterView`，禁止大纲/全局状态/工具；输出到 `sim_cache/pov/{id}/`。
- **默认模板只挂 `sim` + `character_panel`**；`pov_sim` 是可选内置步骤（自定义工作流可加，
  `PRE_CHAPTER_PERIODIC_IDS` 也预留了它），`character_panel` 内部走 `run_character_panel`
  生成 POV 提案。两者缓存分家，POV 永远不读 author_sim 的产出。

### 伏笔自动回收

写后沉淀（`sediment_chapter`）每章执行 `_auto_close_loops`：正则匹配回收信号词（「原来如此」「真相大白」「谜底揭开」等），与 `open_loops` 的关键词子串匹配，命中自动 `close_loop` 标记已回收。漏报可接受（注意力尾部持续提醒），误报有审计链可追溯。

## 规划步骤表（`_PLANNING_STEPS`）

| id | 技能 | 输入 | 输出 |
|----|------|------|------|
| `ideation` | 立意规划 | — | `planning/立意.md` |
| `outline` | 故事结构 | 立意 | `planning/大纲.md` |
| `characters` | 人物设定 | 大纲 | `planning/人物设定.md` |
| `world` | 世界观构建 | 大纲 + 人物设定 | `planning/世界观.md` |
| `timeline` | 故事结构 | 大纲 + 人物 + 世界观 | `planning/时间线.md` |
| `main_plot` | 故事结构 | 大纲 + 人物 + 世界观 | `planning/主线.md` |
| `sub_plot` | 故事结构 | 大纲 + 主线 | `planning/支线.md` |
| `foreshadow` | 伏笔设计 | 大纲 + 主线 + 支线 | `planning/伏笔.md` |
| `chapter_outline` | 故事结构 | 立意 + 大纲 + 主线 + 伏笔 | `planning/章节细纲.md` |

> **默认串行**：每步通过 `input_files` 引用上游产物，保证前后关联（立意→大纲→人物→世界观→时间线→主线→支线→伏笔→章节细纲 逐级递进）。只有在步骤显式声明 `depends_on` 时才启用 DAG 并发；内置模板不声明，保持串行。

大纲/主线/支线/伏笔的 prompt 均强调 `{target_chapters}` 篇幅匹配，防止剧情前 100 章写完。

**章节细纲**（`chapter_outline`，内置 handler）：全书逐章剧情骨架（`## 第N章` + 事件/转折/章末钩子），**分批 15 章**生成，防单次输出截断。写正文时只注入本章那一段（`=== 本章细纲 ===`）。每 5 章由 `update_chapter_outline` 按实际走向修订**未来 10 章**，再按章号 splice 回原文；覆盖不足 80% 时拒绝写盘、保留旧文件。不再要求模型重写整本书（100 章约 1.3 万字，必然截断）。
续写工作流也包含 `chapter_outline`（optional）：老项目缺细纲时先补一份，已有则智能跳过。

## 执行语义（`WorkflowRunner`）

| 特性 | 口径 |
|------|------|
| Agent 匹配 | `find_agent(skill)` 按 `needs` 技能匹配；`optional` 找不到则跳过；同技能多 Agent 轮换需显式开 `rotate_agents`（默认关闭——规划链依赖同一 Agent 的历史传递） |
| 智能跳过 | 已有内容的章节在 LLM 调用前跳过 |
| 标题约束 | 已有文件名的章节，prompt 注入标题约束防改名 |
| 章节命名 | 从响应提取标题生成 `chapters/{n}_{title}.txt` |
| 覆盖写 | 章节步骤已有非空文件时跳过（不覆写）；润色步骤就地覆写正文 |
| 断点恢复 | 进度落 `workflow.json`（合并写，不丢定义）；重启时单步跳过 done、循环步骤从 **`current+1`** 续跑（`current`=已完成章后链路与沉淀的最后一章）；启动时询问「从断点继续」。内置模板会先用 `refresh_builtin_workflow` 刷新提示词/技能（步骤 id 序列一致才刷新，自定义工作流保留原样） |
| 并发步骤 | 未声明 `depends_on`：连续 `parallel_ok` 一组 `asyncio.gather`；声明后：拓扑分层、同层并发、层间串行。失败步骤不得被标 done |
| 失败重试 | `retry` + `retry_delay` 指数退避；`WorkflowError`（缺 Agent）与 `ChapterWriteRejected`（正文校验失败）不重试 |
| 单步超时 | `timeout` 用 `asyncio.wait_for`；超时按普通失败处理，可重试 |
| 用量统计 | `BaseAgent.usage_sink` 由 runner 注入，标准步骤 + 内置步骤 + 工具循环全部计入 `total_usage` |
| 运行日志 | 每次 run 写 `runs/*.jsonl`：run_start/step_start/step_end/step_error/step_retry/tool_call/tool_result/story_track/run_end，含耗时与 token |
| 章节写失败 | 内容校验失败抛 `ChapterWriteRejected`，记录错误但不推进 `current`，恢复时重试该章 |
| 故事线反哺 | `world_state_update` 与每章 `sediment` 完成后调用 `_sync_story_ledger(n)`（纯规则、零 LLM），写 `story_threads.json` 并 `on_event("story_track")` |
| 历史治理 | 逐章循环**每轮迭代清空全部 Agent 历史**（跨章连贯由 ContextBuilder 负责）；`_build_messages` 另有 24K token 历史预算兜底 |
| 错误容忍 | 定时步骤失败记 `error` 并继续（恢复时自动重试）；单章写作失败记入 `_errors` 并保留进度洞（`current` 不越过失败章）；**连续 2 章失败（断网/API 不可达）自动中止整跑**，恢复网络后从断点继续，不把后面几百章刷成 error；规划阶段保持 fail-fast；可选普通步骤失败记 `error` 跳过 |
| 回调 | `on_step_start` / `on_step_end` / `on_error` / `on_event` / `on_chunk`，由 `WorkflowThread` 转 Qt 信号 |
| 停止 | 步骤边界优雅停止 + 取消进行中的 LLM 调用（秒级生效） |
| 看门狗 | 5 分钟无任何步骤/流式事件（`NOVEL_WRITER_WATCHDOG`）→ 强制取消任务并提示从断点继续；兜底同步工具/embedding/事件循环死等 |
| 目标章节数 | `build_workflow` 从立意自动解析分卷求和（如「30章→35章→35章」=100），与 `end_chapter` 差 >15% 时以规划为准 |
| Token 用量 | 累计 `LLMResponse.usage`，随进度落 `progress["_usage"]` |

## 内置步骤注册表（`BUILTIN_STEP_HANDLERS`）

```python
@handler("toc")
async def _run_toc(runner, step, n): ...

# 注册键（15 个）：toc / fix_titles / chapter_summary / world_state_update /
#   quality_check / proofread / review / review_panel / percept_extract /
#   character_panel / offscreen_tick / seal_chapter / pov_sim /
#   chapter_outline / update_chapter_outline
```

统一签名 `(runner, step, n)`，自行负责回调与异常。runner 按 `step.id` 分发，替代 if/elif 长链。

| 步骤 | 实现 |
|------|------|
| `toc` | `project_io.generate_toc` |
| `fix_titles` | 只修空/占位/重复标题：先规则筛查，正常标题一个不动；只把问题章节前 500 字给 LLM，并用现有标题做风格参考 |
| `chapter_summary` | LLM 生成结构化章节概要 |
| `world_state_update` | LLM 结构化更新 `world_state.json` |
| `quality_check` | 纯规则 `QualityChecker` |
| `proofread` | 输出含 `{n}` 为逐章模式；否则**全书分批校对**（按 60K token 预算打包），聚合成 `review/校对报告.md` |
| `review` | **全书分批审核**（批=章节全文+规划摘要），各批发现聚合为 `review/审核报告.md` |
| `review_panel` | 三视角并行审最近几章（`REVIEW_PANEL_LENSES`）→ 主编聚合 → `review/会审报告_第a-b章.md`，同时反模式入库 |
| `percept_extract` | 正文 → `CanonEvent`（observable/hidden/known_by），幂等（已有事件则跳过） |
| `character_panel` | 仅 `auto_sim` 角色，多 POV 提案 + 导演裁决，写 `sim_cache/pov` 与场景 brief |
| `offscreen_tick` | 每 5 章批量推进离场角色，受 `enable_offscreen_tick` 开关控制 |
| `seal_chapter` | 定稿封印（`seal_chapters` 开关），写正典并禁止后续覆写 |
| `pov_sim` | 角色隔离视角推演（默认模板未挂载，自定义工作流可用） |
| `chapter_outline` | 分批 15 章生成 `planning/章节细纲.md` |
| `update_chapter_outline` | 每 5 章只修订未来 10 章，按章 splice，覆盖 <80% 拒绝写盘 |

## 边界与已知限制

- `every` 的计数基准是**章号 n**（`n % every == 0`），不是「执行次数」；第 1、2 章没有灵感（every=3）。
- `fix_titles` 的 JSON 提取对 LLM 输出格式敏感，解析失败则跳过改名。
- 反哺步骤 `update_planning=True` 会**覆盖**规划文件，prompt 要求「保留原有结构+末尾追加」，但无代码级 diff 保护。
- `fill_gaps` 模式在 `build_workflow` 里按 `start..end` 逐章查 `chapters/`（空文件也算缺失），
  生成单个 `chapter` 步骤 + `project["_gaps"]` 列表；不是「fix_titles + 逐章循环」。
- 逐章循环内的 LLM 调用不再携带前几章对话历史（设计如此，防上下文爆炸）；若模型风格强依赖自身前文，靠 prev_chapters 全文与概要衔接。
- `compress_context` 仍按魔法字符串给 part 分类，章节正文含 `=== 第` 等标记时会误分类（已知债务，未重构）。

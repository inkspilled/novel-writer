# 工作流引擎算法

> 引擎：`src/novel_writer/core/workflow/`（`definition.py` / `runner.py` / `builtin_steps.py` / `constants.py`）
> 调用点：UI `workflow_panel.py`（WorkflowThread 后台执行）、`workflow_bar.py`（进度）
> 测试：`tests/test_workflow.py`、`tests/test_workflow_package.py`

## 一句话总结

可组合的工作流引擎：五种模式由**共享步骤列表**拼装；步骤支持 `every` 定时触发、`repeat` 循环、断点恢复、智能跳过；特殊步骤走 `BUILTIN_STEP_HANDLERS` 注册表分发，不走标准 LLM 路径。

## 五种模式（`WorkflowMode`）

| 模式 | id | 步骤组合 | 用途 |
|------|----|----------|------|
| 新书全流程 | `new_book` | 规划 + fix_titles + 逐章循环 | 从立意到审校 |
| 新书立意 | `new_book_planning` | 仅规划 | 只生成规划文档 |
| 续写 | `continue` | fix_titles + 逐章循环 | 从已有章节继续 |
| 查漏补缺 | `fill_gaps` | fix_titles + 逐章循环（缺章检测） | 补写缺失章节 |
| 校验 | `validate` | 校验小步骤集 | 审核+校对已有章节 |

模板由单一来源组合，避免四份互相复制：

```
DEFAULT   = _PLANNING_STEPS + [_FIX_TITLES_STEP] + _CYCLE_STEPS
CONTINUE  = [_FIX_TITLES_STEP] + _CYCLE_STEPS
PLANNING  = _PLANNING_STEPS
VALIDATE  = 校验专用小步骤集
```

## 步骤数据结构

```python
@dataclass
class WorkflowStep:
    id: str                    # 步骤 id（也是内置处理器注册键）
    needs: str                 # 需要的技能名（Agent 匹配用）
    prompt: str                # 指令模板，支持 {变量} 插值
    input_files: list[str]     # 输入文件（支持通配符 / prev_chapters）
    output: str                # 输出路径，支持 {n} 占位
    repeat: int = 0            # 循环次数（0=不循环）
    every: int = 0             # 每隔 N 章执行一次（0=每章）
    optional: bool = False     # 找不到 Agent 时跳过
    update_planning: bool = False  # 强制覆盖 planning/（反哺步骤）
```

## 逐章循环步骤表（`_CYCLE_STEPS`）

| id | 技能 | every | 备注 |
|----|------|-------|------|
| `inspiration` | 灵感激发 | 3 | 产出 3 个转折方向 |
| `sim` | 角色推演 | 1 | 见[角色推演算法](角色推演算法.md) |
| `chapter` | 正文写作 | 1 | 主步骤 |
| `chapter_summary` | — | 1 | **内置**（非 LLM） |
| `world_state_update` | — | 1 | **内置** |
| `toc` | — | 1 | **内置** |
| `polish` | 润色 | 2 | 就地覆盖正文 |
| `proofread` | 错别字检查 | 1 | 输出 `review/校对报告.md` |
| `summary` | 剧情摘要 | 5 | 输出 `summary/第1-{n}章摘要.md` |
| `update_outline` | 故事结构 | 10 | `update_planning=True` |
| `update_characters` | 人物设定 | 10 | `update_planning=True` |
| `update_foreshadow` | 伏笔设计 | 10 | `update_planning=True` |
| `quality_check` | — | 1 | **内置**，见[质量检查算法](质量检查算法.md) |
| `review` | 剧情审查 | — | 全书审校（循环末） |

## 规划步骤表（`_PLANNING_STEPS`）

| id | 技能 | 输入 | 输出 |
|----|------|------|------|
| `ideation` | 立意规划 | — | `planning/立意.md` |
| `outline` | 故事结构 | 立意 | `planning/大纲.md` |
| `characters` | 人物设定 | 大纲 | `planning/人物设定.md` |
| `world` | 世界观构建 | 大纲 + 人物设定 | `planning/世界观.md` |
| `timeline` | 故事结构 | 大纲 + 人物 + 世界观 | `planning/时间线.md` |
| `main_plot` | 故事结构 | 大纲 + 人物 + 世界观 | `planning/主线.md` |
| `sub_plot` | 故事结构 | 大纲 + 主线 | `planning/支线.md` |
| `foreshadow` | 伏笔设计 | 大纲 + 主线 + 支线 | `planning/伏笔.md` |

> **必须串行**：每步通过 `input_files` 引用上游产物，保证前后关联（立意→大纲→人物→世界观→时间线→主线→支线→伏笔 逐级递进）。不可并发，否则各写各的导致题材/风格割裂。

大纲/主线/支线/伏笔的 prompt 均强调 `{target_chapters}` 篇幅匹配，防止剧情前 100 章写完。

## 执行语义（`WorkflowRunner`）

| 特性 | 口径 |
|------|------|
| Agent 匹配 | `find_agent(skill)` 按 `needs` 技能匹配；`optional` 找不到则跳过 |
| 智能跳过 | 已有内容的章节在 LLM 调用前跳过 |
| 标题约束 | 已有文件名的章节，prompt 注入标题约束防改名 |
| 章节命名 | 从响应提取标题生成 `chapters/{n}_{title}.txt` |
| 覆盖写 | 已有章节文件复用覆盖，不重复创建 |
| 断点恢复 | 进度落 `workflow.json`，可从中断处继续 |
| 回调 | `on_step_start` / `on_step_end` 驱动 UI 进度 |

## 内置步骤注册表（`BUILTIN_STEP_HANDLERS`）

```python
@handler("toc")
async def _run_toc(runner, step, n): ...

# 注册键：toc / fix_titles / chapter_summary / world_state_update / quality_check
```

统一签名 `(runner, step, n)`，自行负责回调与异常。runner 按 `step.id` 分发，替代 if/elif 长链。

| 步骤 | 实现 |
|------|------|
| `toc` | `project_io.generate_toc` |
| `fix_titles` | LLM 校准标题（每章前 500 字）→ JSON 提取 → 批量改名 |
| `chapter_summary` | LLM 生成结构化章节概要 |
| `world_state_update` | LLM 结构化更新 `world_state.json` |
| `quality_check` | 纯规则 `QualityChecker` |

## 技能名（`constants.py`）

`SKILL_PROOFREAD` / `SKILL_REVIEW` / `SKILL_TYPO_CHECK` 等常量统一引用，避免字符串魔改。

## 边界与已知限制

- `every` 的计数基准是**章号 n**（`n % every == 0`），不是「执行次数」。
- `fix_titles` 的 JSON 提取对 LLM 输出格式敏感，解析失败则跳过改名。
- 反哺步骤 `update_planning=True` 会**覆盖**规划文件，prompt 要求「保留原有结构+末尾追加」，但无代码级 diff 保护。
- `fill_gaps` 模式的缺章检测依赖 `scan_chapters` 的文件名序号连续性判断。

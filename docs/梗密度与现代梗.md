# 梗密度与现代梗

> 引擎：`src/novel_writer/core/meme_style.py`
> 注入：`workflow/context.py`（仅 `chapter` 头部）+ `workflow/definition.py` 步骤提示词
> 落盘：`meta.json` 的 `meme_level` 字段（`无 / 少 / 中 / 高`，默认「少」）
> 测试：`tests/test_meme_style.py`

## 一句话总结

把「能不能玩现代梗、一章玩几个、谁能玩」做成项目级开关：默认「少」（1–2 个/章，只放在主角吐槽、旁白和熟人对话里），可关到「无」，也可开到「中/高」。梗是调味，不能改变剧情走向，也不能让长老张口就是 KPI。

## 四档口径

| 档位 | 每章目标 | 上限 | 适用 |
|------|----------|------|------|
| `无` | 0 | 0 | 正剧、历史、严肃题材；一个现代梗都不用 |
| `少`（默认） | 1–2 | 3 | 大多数长篇：偶尔一句吐槽，不破坏沉浸 |
| `中` | 3–5 | 6 | 轻松/职场/错位喜剧，梗是稳定笑点 |
| `高` | 6–10 | 12 | 整活向；仍要求服务人物和冲突 |

「每章」按 3000–4000 字估算；短章按比例折算。字数不足 300 的文本只统计、不判超标。

## 注入链路

```
项目 meta.meme_level
  → workflow_mixin / build_workflow 写入 project_info
  → ContextBuilder.build(step_id="chapter")
      → 头部注入 `=== 【梗密度 · 档位】 ===`
  → 写作 Agent 的 system_prompt + chapter-craft 技能也写死「按梗密度执行」
```

- **只在新写正文时加梗**：`_MEME_STEP_IDS = {"chapter"}`；润色不注入梗约束，提示词要求「保留原梗，不新增也不删改」。
- 与 [叙述语言](叙述语言与大白话约束.md) 联动：梗密度=无时，语言约束会写「仙侠/历史题材不用现代流行语」；开了梗则改成「现代梗按【梗密度】控制，不要超量」，避免两条规则打架。
- 题材提醒：仙侠/武侠/历史/玄幻/架空等「古代向」题材，现代梗只能作为主角/旁白的错位吐槽，世界内人物不能把 996/KPI 当日常词，也不出现手机、网络、APP 等具体现代物件（除非设定允许）。都市/职场题材则可自然进入对话。

## 梗的选择

优先级写死在约束里：

1. **制度类长期梗**：996、KPI、画饼、摸鱼、内卷、躺平、打工人、社畜、背锅、裁员、团建、打卡——不容易过时，也贴「劳动仲裁」题材。
2. **少用短视频梗**：一年就过气的热词，写完就尬。
3. **不解释梗**：不写「这就像现代的 996 一样」；读者懂就懂，不懂也不影响剧情。
4. **重复控制**：同一个梗一章最多 1 次；连续两段不要都玩梗；死亡/诀别/决战收住。
5. **人设底线**：长老不喊「绝绝子」，反派不玩「摸鱼」；梗不改变事件走向。

## 体检口径（`measure_memes`）

高信号词表分三类：职场（996/KPI/画饼/摸鱼/内卷/躺平/社畜/背锅/裁员/团建/打卡…）、网络（破防/整活/摆烂/逆天/社死/草台班子/班味/热搜/弹幕…）、时代错位（手机/微信/电脑/网络/直播/系统提示/氪金/抽卡/12345/12333…）。只收高信号词，**不把「仲裁/合同/法院」这类设定必需词算成梗**。

结果写入 `QualityReport.meme_metrics` / `meme_issues`，在质量报告里单列「梗密度」小节；**不参与总分**。提示包括：无档检测到梗、中/高档偏少、超出上限、同一个梗重复 ≥3 次。

## 边界

- 词表是代理指标：反讽、谐音梗、剧情梗检测不到；命中也不代表一定是梗。
- 模型生成的梗受其训练语料影响，可能偏旧；约束里已要求优先「制度类长期梗」，但仍需作者扫一眼。
- 梗密度是项目级设置，不按章单独调；想让某一章「收住」可在细纲或写作指令里临时注明。
- 已写章节不会自动改写；新设置只影响之后生成的章节。

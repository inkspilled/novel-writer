# 短剧制作工作流

短剧页签顶部是「制作流水线」主轴：**① 生成剧本 → ② 生成素材 → ③ 生成本集视频** 三个主按钮，旁边是各阶段状态灯（剧本/素材/视频）和失败项重试。三个按钮分别对应「准备剧本与分镜」（全部待用）、「生成设定图」（当前集）和「制作本集视频」（当前集），背后自动接续缺失环节。单步工具（重编圣经、故事冷读、首尾帧提示词、后期、复盘等）仍收在右侧「执行模式」的「显示单步工具」里，按需单独补做或重审。

## 配置

- 企划填写画风、配色、配乐说明、原曲文件、字幕、参考片路径、要求与偏好原文。
- 每套妆发可用独立人物资产记录，在「备注」填写该造型的妆容、假发、发饰和连续性细节。
- 图片设置支持图片 API、ComfyUI、Codex CLI。参考图编辑走 `/images/edits`、ComfyUI 一致性工作流或 Codex `-i`；不支持编辑时明确失败，不静默丢弃参考图。
- 视频设置支持 ComfyUI 或 Seedance。Seedance 优先读 `ARK_API_KEY`，也可填写本机密钥；填写账号可用的模型。
- 需要 Python、Pillow、ffmpeg、ffprobe；视觉审核模型必须支持图片。开工自检只检查本机工具与配置。

## 实际顺序

1. 开工自检：导出缺失工具、四问状态与总导演提示词。制作本集遇到必要工具/服务缺失会停止。
2. 可选参考片：抽帧并把实际帧分批交给视觉模型，保存机位/进出画比例分析；后续分镜提示词会读取当前参考片对应的分析。抽帧推断不等于精确运动测量。
3. 缺剧本时先准备圣经并智能分集，分集规划和剧本经过独立审核与监督。
4. 故事冷读：审核只收到故事，不带导演结论；通过后监督核对要求，再由用户阅读并确认故事。
5. 分镜审核和设定图：登记资产，审核提示词后补齐缺少的图片，再做视觉审核和确认。人物生成两层参考——头肩定妆四角度（正面/左侧/右侧/正后方）与全身三视图（正面/侧面/背面）；场景为 360° 环景加正反向透视；道具为正面/侧面/背面三视图。同层侧面/背面引用该层正面照生成。龙套/临时场景/通用道具先问跨项目**公用素材库**：AI 判定可复用就直接拷贝库图（不出图、不走提示词审核），视觉审核和人工确认照走；生成完的通用素材 AI 判定后自动回存库（详见[短剧素材与ComfyUI](短剧素材与ComfyUI.md)）。
6. 画风确认：输出 1920×1080 色块示意、彩色/黑白总表和逐场色表，展示已有设定图，由用户确认。色块明暗检查只检查示意布局，不保证正式图质量。
7. 首尾帧：先审方案再出图；通常先生成尾帧，再以尾帧编辑首帧；同地点同机位引用上一镜，推近镜头使用同图裁切放大。首尾帧必须同尺寸、符合剧集画幅。镜头引用资产优先走 shot→asset 结构化引用表（分镜提取时落盘，改名不断链）；人物参考按景别分层——远景/全景/中景优先全身三视图，特写/近景用头肩定妆。
8. 首尾帧与提交审核合为逐镜审核。每镜提供实际首帧、尾帧、叠图、手机缩略图及匹配的设定图，对照首尾帧检查项和视频提示词。
9. 逐镜提交：必须有每个镜号明确「通过」的记录。故事、圣经、视觉参数、分镜、首尾帧说明、资产或图片变动后，原审核自动失效。审核通过后提交视频。
10. 后期：按镜头目标时长剪辑；原曲拍点用于调整实际切点。修复只作用于指定镜号，归一化为 FFV1/PCM 无损中间文件，处理转场与音频，输出 MP4；竖屏放大为 1080×1920。字幕依据剧本在后期生成。
11. 全片复核：先完整解码，再逐镜取多张全分辨率帧、切点前后各三帧。审核收到全片顺序总表和细节帧，不带导演故事结论；模型无法凭静态帧判断动态手感和声音，最后必须由用户播放确认。
12. 复盘：将画风、提示词、错误、修复办法和经验存到 `drama/retro/`。

这些阶段也都有独立执行模式。分镜页「预览本集」菜单提供首尾帧居中裁切、指定区域贴回；贴回区域之外的原图像素保持不变，修改后必须重新审核。

## 失败与重试

- 每个阶段跑完会把失败项写进 `drama/failures.json`（阶段、目标、原因）。流水线主轴显示「⚠ 设定图 2 项 · 视频片段 1 项」，菜单里**只重试失败项**：已成功的靠内容指纹增量跳过，不会重做。
- ComfyUI 连接类错误（连不上/读超时）自动重试一次；工作流执行错误不重试。
- Seedance 提交中断留下的 submitting/submitted 任务，用主轴的「查云端任务」对账：成功则下载认领进片段目录（clips manifest 按 input_hash 指纹命中，续跑不重复烧钱），失败则清记录可重新提交，仍在生成则下次再查。
- 分集/分镜/首尾帧说明逐集失败不打断整批；重新运行同一模式即可从断点接续。

## 后期参数

企划「后期参数」是表单：转场（类型/时长）、调色、放大、帧率、保留原片音频、BT.709 解码，以及片段修复（去首帧黑帧/尾帧冻结/重平衡 + 作用镜号）。表单落盘为 `series.json` 的 `post_options`：

```json
{
  "transitions": true,
  "transition_kind": "fade",
  "transition_seconds": 0.4,
  "grade": true,
  "upscale": true,
  "to_709": false,
  "use_source_audio": false,
  "fps": 24,
  "repair": {"shots": ["E01-S001"], "drop_first": true, "freeze_tail": true}
}
```

转场还支持 ffmpeg 的 wipe/slide 等类型；`motion_blur` 是切点附近 12 帧混合近似，不能宣称物理半帧快门。`repair` 可选 `drop_first`、`freeze_tail`、`rebalance`，必须指定 `shots`。重拍前先运行修复或使用局部修图，避免原样反复提交。

默认不使用模型自带音轨；明确选择 `use_source_audio: true` 才保留，原曲文件存在时使用原曲配乐。`to_709` 只在明确源为 BT.601 时开启，不能把所有 MP4 都当作 BT.601。亮度/饱和度调整不包含人物肤色和强调色的语义蒙版保护，需要人工检查。

## 任务续跑

- 请求时长按整数秒向上取整，并满足模型最短时长（2.0/2.5 至少 4 秒）；不允许通过附加参数覆盖已选模型、内容、时长和分辨率。API 的生成规格参数放在请求体顶层，依据[火山方舟创建视频任务文档](https://docs.volcengine.com/docs/ark/create-video-generation-task-api?lang=zh)。
- 提交视频后保存服务商任务 ID。下载失败后可查询和下载原任务，不重复创建；重复运行会跳过材料和文件均未变化的片段。
- 提交结果不明时，用「查云端任务」对账（见上），避免重复提交。
- 服务明确拒绝请求后可重新运行。生成中断时保留已经完成的片段。
- 剧本、圣经、首尾帧、片段和后期产物保留版本；已完成图片和片段各有内容指纹用于续跑。

## 追溯

- 每次出图/出视频都往 `drama/generation_records.jsonl` 落一条：目标（资产/角度、首尾帧、片段）、服务与模型、工作流文件及 hash、seed、提示词与负面词摘要、参考图 digest、输出文件 digest、时间。资产页「生成记录」按选中资产查它的完整配方，seed 是确定性算法，换机器可复现。
- 旧图/旧分镜进 `versions/` 时登记 `drama/versions_index.jsonl`（属主、旧文件、被谁替换），历史对得上号。
- 分镜与资产的引用关系在 `storyboard/epNNN_refs.json`（shot_id → 人物/地点/道具的 asset_id），首尾帧生成和视频编排都吃这张表。

## 文件与代码

| 内容 | 文件/入口 |

独立上下文的模型角色由桌面程序顺序编排，不是常驻的四个操作系统线程。模型判读仍可能漏错；确认和快照核验是程序强制检查，审美与剧情判断不能用规则保证。

## 验证

`tests/test_drama_production.py` 覆盖图片实际传递、审核失效、云端任务提交和续取及离线制作全链。`tests/test_drama_post_integration.py` 在 PATH 有 ffmpeg/ffprobe 时实际验证三种拼接、字幕、音轨、时长、切点抽帧和竖屏 1080p；没有工具时明确跳过。测试不调用真实生成服务。

## 审查补强

- 审核期间材料变化时拒绝放行；通过结论保存审核开始时的版本，切换视频规格也会使旧结论失效。
- 同项目的云端生成持有跨进程任务锁，防止重复提交。
- 未通过或未确认的设定图续跑时必须重审，已有图片不必重新生成。
- 手工修过的首尾帧续跑时先询问是否采用修改，不直接重画覆盖；实际提交使用审核后冻结的输入副本。
- 分镜页启动任务时采用该页当前集，完成后保留该集；镜号重复或格式错误时阻止制作。
- 全片总表按真实时间排序并保留原画幅；相邻镜头图片实际送入提交前审核。

# 长期记忆算法

> 引擎：`src/novel_writer/core/memory.py` → `MemoryScratchpad`
> 落盘：`{project}/memory.json`
> 调用点：写后沉淀、章节四维追踪、上下文组装（角色状态合并、未解伏笔）
> 测试：暂无专属测试

## 一句话总结

跨章事实的结构化长期存储，**11 个桶**分类管理；同键去重（新值覆盖旧值，旧值标记 `outdated` 保留审计）；提供按桶/主题查询、伏笔开关、压缩和 LLM 上下文文本生成。

## 11 个桶

| 桶 id | 中文标签 | 内容 |
|-------|----------|------|
| `character_state` | 角色状态 | 等级/位置/伤势/情绪 |
| `story_facts` | 剧情事实 | 关键事件/转折 |
| `world_rules` | 世界规则 | 已揭示的力量体系/禁忌 |
| `timeline` | 时间线 | 时间线事件 |
| `open_loops` | 未解伏笔 | 未回收的悬念 |
| `reader_promises` | 读者期待 | 待兑现的承诺 |
| `relationships` | 人物关系 | 关系变化 |
| `resources` | 资源账本 | 物品获得/失去 |
| `emotional_arcs` | 情感弧线 | 情绪变化追踪 |
| `info_boundary` | 信息边界 | 谁知道什么/谁不知道什么 |
| `subplots` | 支线进度 | 感情线/复仇线/成长线等 |

## 记忆项与去重

```python
@dataclass
class MemoryItem:
    id: str = ""              # sha256(dedup_key + source_chapter)[:16]，自动生成
    category: str = ""        # 桶 id
    subject: str = ""         # 主体（角色名/支线名/事件名）
    aspect: str = ""          # 方面（如「持有:灵石」）
    value: str = ""           # 值
    status: str = "active"    # active / outdated / contradicted
    source_chapter: int = 0
    evidence: str = ""
    payload: dict = {}
```

**去重键**（`dedup_key`）：

| 桶 | 键 |
|----|----|
| `open_loops` / `reader_promises` | `category:subject` |
| 其余 | `category:subject:aspect` |

`upsert` 语义：同键**所有 active 旧值**标记为 `outdated`，再追加新值。审计链完整保留。

## 查询与开关

| 方法 | 语义 |
|------|------|
| `query(category, subject, status)` | 过滤桶/主体子串/状态 |
| `get_active(category)` | 指定桶全部 active 项 |
| `get_open_loops(limit)` | 未解伏笔，按 `payload.urgency` 降序，默认 10 条 |
| `close_loop(subject, ch)` | 伏笔置 `outdated` + 在 `story_facts` 记一条回收事件 |

## 压缩（`compact`）

```
保留 = 所有 active 项
     + 每个同键(subject:aspect)的最新 1 条 outdated
```

其余 outdated 丢弃。写后沉淀在 `save()` 前调用，防止审计链无限膨胀。

## 上下文文本（`build_memory_text`）

每桶取前 `limit_per_bucket`（默认 5）条 active，输出：

```
【角色状态】
- [凌尘] 实力变化: 凌尘突破（第3章）

【未解伏笔】
- [第2章伏笔] 悬念: 竟然发现灵脉异常（第2章）
```

> 注意：上下文组装**并未调用** `build_memory_text` 全量注入，而是走更精细的路径：
> - 角色状态 → `build_merged_character_states`（与 world_state 合并去重）
> - 未解伏笔 → `get_open_loops(limit=8)`
>
> `build_memory_text` 留给对话/调试等全量场景。

## 边界与已知限制

- `MemoryItem` 无 `field` 字段，但 `close_loop` 调用时传了 `field="伏笔回收"` —— 该参数**会被 dataclass 丢弃**（不存在于定义），实际只写 `value` 文本。
- `status` 枚举含 `contradicted`，当前**无写入方**，为预留。
- `compact` 的 outdated 去重键是 `subject:aspect`，与 `dedup_key`（含 category）不完全一致——同 subject+aspect 跨桶时压缩可能误并（实际各桶 subject 语义不同，风险低）。
- 全量 JSON 读写，大书（数千条）时 `upsert` 线性扫描，性能可接受但非最优。

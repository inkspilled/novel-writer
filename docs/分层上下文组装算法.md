# 分层上下文组装算法

> 引擎：`src/novel_writer/core/workflow/context.py` → `ContextBuilder` / `compress_context` / `estimate_tokens`
> 调用点：工作流 runner 在每次 LLM 步骤前组装 prompt 上下文
> 测试：`tests/test_workflow.py`（部分覆盖）

## 一句话总结

**注意力优化布局**（对抗 U 形注意力曲线）：头=硬约束+活性记忆卡 / 中=参考材料 / 尾=伏笔+信息差。按步骤类型注入四层上下文（GLOBAL → WORLD → NARRATIVE → WORKING），超限按优先级压缩。活性记忆卡按本章出场实体精准注入，不全量 dump。

## 注意力优化布局

```
┌─ 头部（注意力 70-75%）─┐
│ 项目元信息              │ ← 模型最先看到
│ 角色锚定硬约束          │
│ 活性记忆卡（本章相关实体）│
├─ 中部（注意力 55-60%）───┤
│ 世界设定 / 角色状态表    │ ← 可压缩裁剪
│ 本章大纲 / 细纲         │
│ 故事线台账（剧情类步骤） │
│ 规划文档 RAG 片段       │
│ 历史章节全文/概要       │
├─ 尾部（注意力 70-75%）─┤
│ ⚠ 未解伏笔（需近期处理） │ ← 模型最后看到
│ ⚠ 读者承诺 / 信息边界    │
│ 🔗 上章承接点           │
│ 写作禁忌 / 追读力指导    │
└──────────────────────┘
```

### 活性记忆卡（`_build_active_memory_cards`）

从大纲确定性提取本章出场的角色/地点名 → 精准拉取各自的状态卡（境界/位置/背包/技能/近 3 章变化/资源得失/情绪）。**不相关实体不入卡**，避免注意力稀释。

### 注意力尾部（`_build_attention_tail`）

放在上下文末尾的高注意力区：未解伏笔（`get_open_loops`，按[动态紧急度](因果相关性算法.md)降序、超期项标「优先回收」）、近期已回收清单（防复收）、读者承诺、信息边界（谁不知道什么）、上章承接点、反模式禁忌、追读力指导。

## Token 估算与预算

```
estimate_tokens(text) = cn_chars × 1.5 + en_words × 1.3
MAX_CONTEXT_TOKENS    = 48_000    # 预留 system/输出/工具往返空间
```

粗估口径，中英混排可接受；不做真实 tokenizer。

## 四层上下文（ContextTier）

| Tier | 名称 | 注入内容 | 典型 token |
|------|------|----------|------------|
| 0 | `GLOBAL` | 项目元信息（书名/题材/风格/主题） | ~50 |
| 1 | `WORLD` | + 世界设定简报、角色状态（合并）、规划文档（RAG 片段）、角色约束 | ~500 |
| 2 | `NARRATIVE` | + 剧情摘要、未解伏笔、反模式禁忌、追读力指导 | ~2000 |
| 3 | `WORKING` | + 上章回顾、角色推演、章节概要（近 5 章）、近 2 章全文、章节 RAG | ~4000+ |

### 步骤 → 层级映射（`STEP_CONTEXT_TIERS`）

| 层级 | 步骤 |
|------|------|
| GLOBAL | `toc` `fix_titles` `chapter_summary` `ideation` `outline` `proofread` `quality_check` |
| WORLD | `characters` `world` `timeline` `main_plot` `sub_plot` `foreshadow` `chapter_outline` `sim` `world_state_update` |
| NARRATIVE | `inspiration` `polish` `review` `summary` `update_outline` `update_characters` `update_foreshadow` `update_chapter_outline` |
| WORKING | `chapter`（默认，未映射步骤也落此层） |

**特殊路径**：`proofread` 不走分层，只注入项目元信息 + 当前章节全文；`pov_sim` 也不走这里，它只用 `CharacterView`（见[角色生命周期与POV推演](角色生命周期与POV推演.md)）。

**故事线台账块**：`_STORY_LEDGER_STEP_IDS`（chapter / chapter_outline / update_chapter_outline /
chapter_summary / summary / inspiration / pov_sim / review / review_panel / quality_check / sim）
在中部额外注入 `=== 故事线台账 ===`，内容是 `StoryLedger.build_context_block`（≤2.6K 字符）：
进行中主线/支线、待回收伏笔（超期标「优先回收」）、最近已发生时间线。纯工具步骤不注入。

## 各层组装明细

### Tier 0 — 项目元信息

```
项目: {title} | 题材: {genre} | 风格: {style} | 主题: {theme}
```

空字段省略。稳定前缀，利于 Prompt Caching。

### Tier 1 — 世界观层

1. **世界设定简报**：世界名 | 时间 | 等级体系（`power_system.levels` 用 `→` 连接）
2. **角色状态合并**（`build_merged_character_states`）：
   - 优先 world_state 的角色（境界/生命/灵力/灵石/位置/背包/技能）
   - memory.character_state 中 world_state 没有的角色再补充
   - 按名字去重
3. **规划文档**：
   - **人物设定.md → 全文注入**（角色约束需要完整信息）
   - 其余规划文档 → **BM25 检索 top-5 片段**（每段截 300 字）；检索异常回退「每文档前 500 字」
4. **角色约束**（`build_character_constraint`，见[节奏控制与角色锚定算法](节奏控制与角色锚定算法.md)）

### Tier 2 — 叙事记忆层

| 块 | 来源 | 口径 |
|----|------|------|
| 剧情摘要 | `project_io.latest_summary` | 最新一份章节摘要 |
| 未解伏笔 | `memory.get_open_loops(limit=6, current_chapter=n, total_chapters=目标章数)` | 按[动态紧急度](因果相关性算法.md)降序，超期项标记 |
| 已回收伏笔 | `memory.story_facts`（`aspect=伏笔回收`，近 8 章） | 防重复回收/复挖已解的坑 |
| 反模式禁忌 | `AntiPatternTracker.get_constraint_text()` | 见[反模式追踪算法](反模式追踪算法.md) |
| 追读力指导 | `ReadingPowerTracker.build_guidance(n)` | 见[追读力算法](追读力算法.md) |
| 故事线台账 | `story_threads.json` → `build_context_block(n)` | 仅 `_STORY_LEDGER_STEP_IDS`；见[故事线台账算法](故事线台账算法.md) |

### Tier 3 — 工作记忆层（仅 `chapter` 等 WORKING 步骤）

| 块 | 口径 |
|----|------|
| 上章要点回顾 | n>1 时取第 n-1 章的 `.summary.md` + 连贯性提醒 |
| 角色推演 | `load_sim_cache(n)`（`sim_cache/sim_{n}.md`） |
| 章节概要 | 最近 **5** 章 summary（`load_chapter_summaries(window=5)`） |
| 近章全文 | 第 n-2、n-1 章 `.txt` 全文 |
| 章节 RAG | 查询=大纲第 n 章描述（`extract_chapter_query`，取 5 行/200 字），索引=前 n-2 章，top-5 |

## 技能包与工具说明（按需注入）

组装完成后，runner 还会按步骤追加两类内容：

| 来源 | 触发 | 内容 | 预算 |
|------|------|------|------|
| `WorkflowStep.skills` | 显式声明（如 chapter 的 `chapter-craft`、polish 的 `continuity`） | 技能 Markdown 正文，标记 `=== 写作技能包 ===` | 无硬上限，全文注入；控制技能包体积 |
| 工具守卫 | 步骤声明 `tools` 且 `tool_rounds>0` | 工具清单 + 使用规则（只在缺事实时调用、预算有限） | ~1k 字 |

技能/工具块与 `other` 类一样**不参与压缩**（属于硬约束），因此长书要控制同时注入的技能数量；按需加载优先走 `use_skill` 工具，而不是在步骤里堆多个 `skills`。故事线台账块同属 `other`（不裁剪），但自身有 2.6K 字符上限。

## 压缩（`compress_context`）

仅当 `total > max_tokens` 时触发。按**类型标记**每个 part，走**两级策略**：

**阶段一（块内缩量，保留信息骨架）**：

| 类型 | 缩量口径 |
|------|----------|
| `rag` | 只留前 2 条，每条正文截 120 字 |
| `chapter_full` | 章号最大（最近）一章保持完整，其余截 600 字 + 截断标记 |
| `planning` | 相关片段块留前 2 条截 100 字；摘要块截 300 字 |
| `sim` | 截 600 字 |

**阶段二（整段丢弃，缩量后仍超限才走）**，按优先级循环整类删除：

| 优先级（先裁） | 标记判据 |
|----------------|----------|
| 1. `rag` | 含 `=== RAG` 或 `[相关度:` |
| 2. `chapter_full` | `=== 第N章 ===\n` 前缀 |
| 3. `planning` | `=== 规划文档` 或 `（摘要）===` |
| 4. `sim` | `=== 角色推演 ===` |
| 5. `summary`（最后裁） | `=== 章节概要 ===` 或前 20 字含「概要」 |

`other` 类两级都不裁。

## Token 优化点

- 角色状态合并去重（world_state + memory）
- 章节概要窗口 10→5，全文窗口 3→2
- 规划文档 RAG 化，不再灌全文
- 压缩两级化：先缩量后丢弃，超限时尽量保信息骨架
- `estimate_tokens` + debug 日志可观测

## 边界与已知限制

- 类型标记靠**字符串前缀匹配**，格式改动会导致块落入 `other` 从而不被压缩。
- 阶段二按「当前真实剩余 token」裁剪（`total_now = sum(tagged)`，丢弃时递减）；**不得**再减历史 `removed_tokens`——曾因双重扣减导致提前停裁、最终上下文超限数倍。
- `proofread` 短路路径**不做压缩**（通常只有一章，风险低）。
- `extract_chapter_query` 只认 `#...第N章` 或 `#...N.` 两种标题形态（`N.` 已加数字边界，`n=1` 不命中「11.」），其他大纲格式会得到空查询（RAG 静默跳过）。
- 未映射的自定义步骤默认 WORKING 层，可能注入过多上下文——自定义步骤应显式配置 tier。

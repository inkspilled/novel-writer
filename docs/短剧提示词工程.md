# 短剧提示词工程（画幅 / 生图 / 分镜 / 视频提示词）

> 性质：`规范`。来源：2026-11 用户分享的多模型 AI 视频工作流文章
> （Claude 导演 / Codex 画师 / Seedance 动画师，作者 Eian）。
>
> 本文只写**本项目已落地**的部分及代码落点，作为对账清单：改了画幅、提示词模板或体检规则，
> 先改代码，再同步本文与 `tests/test_drama_prompt_rules.py`。

## 0 总原则：尽早发现生成问题

文章原话：**文字里能发现的错，不留到图上；图上能发现的错，不留到视频上。**

落地为三道**本地体检**（本地规则）：

| 体检 | 代码入口 | 触发点 | 输出 |
|---|---|---|---|
| 生图提示词体检 | `DramaStore.audit_asset_prompt` | 每张图生成前；「检查资产」汇总 | `check_assets()["prompt_risk"]` |
| 分镜体检 | `DramaStore.audit_storyboard` | 一键分镜落盘后逐镜；分镜页「分镜检查」 | `[{shot_id, issue}]` |
| 视频提示词体检 | `audit_video_prompt` | 导出视频提示词时逐镜 | 缺段/坏写法清单 |

另有**出图后核对**：`save_generated_image(..., expected_size=...)` 读真实像素，
不一致记 `aspect_warning`，汇总到 `check_assets()["aspect_risk"]`。

**生成前检查**：资产页「生成图片」在提交前把 `prompt_risk` 列出来，
弹窗选「仍然生成 / 取消」——文章「我同意才提交」的落地方式；不静默放行。

## 1 画幅：按资产类型，不搞一套竖屏打天下

| 资产类型 | 画幅 | 像素 | 提示词里的画幅句 | 负面词 |
|---|---|---|---|---|
| 人物 `character` | 3:4 竖屏（用户口径「4:3 竖屏」） | 960×1280 | `画幅 3:4 竖构图（宽:高=3:4）` | `ASSET_NEGATIVE` |
| 场景 `location` | 2:1 环景 | 2048×1024 | 360° 等距柱状投影，应用提取两张 1280×720 透视图 | 前置「人物，人影，人脸，手」 |
| 道具 `prop` | 1:1 方图 | 1024×1024 | `画幅 1:1 方构图（宽:高=1:1）` | 前置「人物，人影，人脸，手」 |

说明：**「4:3 竖屏」= 竖着拿的 4:3 画面，即宽:高 = 3:4**（宽 960 / 高 1280）。

画幅同时走两条通路：

1. 参数：`width/height` 传给 ComfyUI 或图片 API（`ImageAPIClient` 会拼成 `size=960x1280`）；
2. 文字：正向词里写死画幅——接口/工作流模板丢参数时，模型仍按文字构图。

像素都是 16 的倍数（latent 对齐）。改画幅要同时改
`ASSET_PROMPT_PLANS[kind]["width"/"height"/"ratio"]` 和测试里的 `asset_canvas` 断言。

### 出图后核对

文章：*Codex 出的图不一定正好是 16:9，提交前要检查一遍，有问题提前裁好；首帧和尾帧尺寸要一样。*

本项目对应：图片落盘时读 PNG/JPEG/GIF/WebP 头拿真实像素，与类型画幅比例差超过 2%
就标 `needs_crop`、读不出尺寸标 `needs_check`，写 `aspect_warning`，「检查资产」列出「画幅不符」。
比例不对的图**不会被设为定妆图**（避免把错误比例固化成后续一致性基准），但图不删——钱已经花了，先留着裁。
手填提示词也不能绕过画幅：`asset_prompt` 发现没写画幅会补一句
`画幅 3:4 竖构图（宽:高=3:4）`，保证文字和 `width/height` 参数一致。

## 2 生图提示词

### 2.1 三类模板（`ASSET_PROMPT_PLANS`）

| 字段 | 人物 | 场景 | 道具 |
|---|---|---|---|
| 后缀 | 单人头肩特写、自然日光、完整头发和肩线 | 全景空镜、画面中只有建筑陈设和自然光、无人物 | 单件特写、物品居中、纯色背景、无人物 |
| 兜底描述 | 展示脸型、妆容、发型和发饰 | 全景空镜，展示空间与氛围 | 单件特写，展示材质颜色造型 |
| 垫图前缀 | 同一人物，保持脸型五官发型服装 | 同一场景，保持结构布局材质 | 同一物品，保持造型颜色材质 |
| 画幅 | 3:4 / 960×1280 | 2:1 / 2048×1024 | 1:1 / 1024×1024 |

### 2.2 写法（都来自文章的错误对照表）

| 规则 | 代码表现 |
|---|---|
| 正面式表述优先 | 场景写「画面中只有建筑结构、室内陈设和自然光」，不写「不要出现人」；ComfyUI 走真正的负面词节点（**内置模板 CFG=1 时不生效，所以正向词必须自带排除信息**）；纯 OpenAI 兼容图片 API 没有该字段时退回「避免：…」的已知降级，配置 `supports_negative_prompt: true` 可改走 `negative_prompt` 字段 |
| 数量写死 | 人物「单人」、道具「单件」；负面词含「多人重复」 |
| 固定特征写死位置 | 人物提示词含纹身/疤痕/胎记却没写左右 → 体检告警「后面每张图都会漂」 |
| 类型锚词 | 手填提示词至少含一个该类型锚词，否则告警「可能画错类型」 |
| 场景/道具挡人 | 正向词不得出现人像词；负面词前置「人物，人影，人脸，手」 |
| 配色单独定 | 企划页「配色」→ `series.palette`，画第一张图前定死，同时进生图提示词和七段式 |
| 垫图保持一致 | `reference_prefix` 按类型分化，只调构图/光线，不换人换景 |

人物妆发照按 [ScreenSkills 妆发记录要求](https://www.screenskills.com/skills-checklists/scripted-film-and-tv/hair-make-up-and-prosthetics-department/hair-and-make-up-designer-skills/) 取正面、左侧、右侧和正后方。四张分别出图，后三张都引用正面照。资产页的「预览图片」可并排查看并标记需要重做的角度。「定妆图（固定）」可填已有的外观参考，用于生成正面照。

场景出图先生成完整环景，画面中心朝主空间或主入口。软件用同一张图提取相隔 180° 的正向和反向透视。提示词要求前景、中景通道与远处后景清楚可辨。复杂场景可在资产备注记录固定锚点的相对方位、数量、色彩和材质，例如「入口正对两根红柱，左侧楼梯通往二层」。场景图审核会检查环景接缝与空间连续性。

### 2.3 体检项（`audit_asset_prompt`）

- 手填提示词缺类型锚词；
- 场景/道具正向词混入人像词（少女/男子/五官/站姿…）；
- 无描述只能走兜底模板（抽卡率高）；
- 资产名疑似多个实体（顿号/「和」/「们」）；
- 人物固定特征没写左右；
- 手填画幅与类型规格冲突（例如人物写了 9:16）。

## 3 分镜

### 3.0 故事阶段（分集编剧提示词）

写剧本时就按文章的故事标准约束，别等分镜再救：

- 每个转折按现实追问：为什么会这样？东西从哪来？够得着吗？
- 开头 3 秒抓人，最抓眼球的画面放最前；
- 每个包袱按「问题 → 主角怎么解决 → 旁人什么反应」写，反应要有先后；
- 避开 AI 拍不出来的画面（同 3.1 的弱点清单）。

落点：`core/drama_adaptation.py` 编剧 prompt 的「【故事红线】」；
改编圣经输出要求第 8 条（`DramaAIWorker._adapt_prompt`）。

### 3.1 写进模型提示词的规则（`DramaAIWorker._storyboard_prompt`）

- 每镜 1–5 秒，生成秒数向上取整、多留 0.5 秒（后期变速留余量），总时长接近单集时长；
- 景别交替，不连续三个同景别；**平视正面全片最多两次**，其余俯拍/仰拍/背后/过肩/透过东西拍；
- `camera` 写「机位，运镜」：机位用平视/俯拍/仰拍/背后/过肩/透过东西，运镜用固定/推近/拉远/摇/跟/手持；
- 构图按黄金比例：头/眼落画面横向 **38% 或 62%**，不放正中；
- 运镜要有理由：跟人物走、推近给特写、拉远交代环境；
- 动作写清原因和手放在哪；表情怎么变写进 `action`；走动/递物写**画面左/右**；
- 每镜写清什么在动（人物动作/镜头/光线/前景遮挡至少一样）；固定机位要让人或物从远到近、穿过画面；
- 多人动作有先后；包袱或转折按「问题 → 主角怎么解决 → 旁人什么反应」三段写；
- 避开 AI 固定弱点：人物交叉、手拿小东西、画面文字、镜子和倒影、左右不对称、
  一镜内换光、一人连做三个动作、俯拍看不到脸、配角太多；
- 道具交代来源；台词用「角色：台词」；`transition` 写清怎么接下一镜；
- 企划的**风格与配色**（`series.style` / `series.palette`）作为「视觉基调」注入提示词，
  每个镜头的 `action` 要写清画面主色和光线来源。

### 3.2 本地体检（`audit_storyboard`）

| 检查 | 阈值 | 对应文章 |
|---|---|---|
| 景别连排 | 连续 3 镜同景别 | 2.2 不要连排同大小画面 |
| 平视正面过多 | 全片 > 2 次 | 2.1 每镜换角度 |
| 时长 | > 5 秒 / ≤ 0 | 每镜 1–5 秒，动作多了会乱 |
| 缺景别/动作/转场 | 空值 | 每镜写清景别、动作、怎么转下一镜 |
| 走/递无方向 | 有走动递物词、无「画面左/右」 | 方向按画面写，防止走反 |
| 多人同时动作 | 含「同时/一齐/众人/同一秒」 | 反应要有先后 |
| 固定机位无动作 | `camera` 含「固定」且无动作词 | 画面死了，像一张图 |
| 模型必翻车画面 | 镜子/倒影/水面/文字/字幕/交叉/换光/不对称/手拿小东西/俯拍无脸/同框超 4 人 | 文章点名的抽卡点 |

只告警、不拦保存：分镜是创作稿，体检负责把问题提前摆到人眼前。
**生成入口**（「生成图片」）会在提交前把提示词风险列出来，弹窗确认「仍然生成 / 取消」——
这就是文章「我同意才提交」的落地方式，而不是让规则静默放行。

## 4 七段式视频提示词

`build_shot_video_prompt(shot, style=..., aspect=..., palette=...)` 把一条分镜展开成七段，
`DramaStore.export_video_prompts()` 导出 Markdown（分镜页「导出视频提示词」）。

七段固定为：**【画风】【镜头】【构图与配色】【人物】【逐秒】【声音】【约束】**。

样例（由分镜自动生成，动作细节可再改）：

```text
【画风】仙侠写实。整段的画风、颜色、人物设计与首帧和尾帧完全一致。
【镜头】整段 3.0 秒，中景，固定机位，不推不拉不摇，不切镜；画幅 9:16 竖屏。
【构图与配色】藏经阁·夜；顾言在画面里，头和眼睛落在画面横向 38% 或 62% 的位置，不放正中；配色：夜戏冷蓝 + 暖黄灯笼，和首帧一致，画面里只有本镜的人和道具。
【人物】顾言；长相、发型、服装和随身固定道具与定妆图一致，全程不变。
【逐秒】
0–0.2 秒：画面完全静止，和首帧一模一样。
0.2–2.7 秒：顾言朝画面左走两步，停在书架前，抬手抽出最上层木匣。
最后 0.3 秒：所有人和物完全停住，画面与尾帧完全一致。
【声音】只有脚步、木匣摩擦声；人物不说话。
【约束】画面里一直只有首帧这几个人和这些东西，脸和身形全程不变，一镜到底；画面干净，没有文字、字幕、水印。
```

转场**不写进生成提示词**（否则和「不切镜」打架），放在导出文件的镜头标题里：
`### E01-S001 · 中景 · 3.0 秒 · 转场：硬切`。
本镜没有人物时（空镜/道具特写），【构图与配色】【人物】【约束】会自动切换成无人版本。

体检（`audit_video_prompt`）：七段是否齐、有没有「人物不说话」「一镜到底」、
结尾有没有对齐尾帧、有没有「同时」、有没有「不要/不能」这类否定句。

导出文件顶部固定带两份人工清单：

1. **提交前审核**：提示词逐句对首尾帧（位置/左右/颜色/人数/道具数量/衣服/表情）、
   两帧机位大小背景一致、和设定图/配色/前后镜头一致、动作有原因且手放哪写清、
   避开同时动作/凭空出现/走反方向/歧义句——最后只写「通过」或「不通过」；
2. **首尾帧自查**：动作要用的东西首帧里必须有、旁人反应提前摆好且不同姿势、
   动作落点留空间、风向统一、缩到手机大小看远景、放大看多余物、
   首尾帧叠图看错位、两帧尺寸一致。

文件末尾还附一段可直接丢给独立 agent 的提示词：

```text
你是审核，只读不改。这些镜头马上要提交视频生成，花的是真钱。
材料：本文件的提示词、首帧、尾帧、设定图、分镜表、配色规则。
逐项核对，放大看图：……
最后只写「通过」或「不通过」。不通过就逐条列出要改什么。
```

导出文件保留人工检查清单；制作工作流现在还会以独立模型上下文执行审核，并实际附上图片。
逐镜通过记录绑定材料指纹，不能只凭清单或一句笼统通过放行。

`ui/drama/production_worker.py`。视频入口不再静默补画图片，必须已有首尾帧图、故事/画风确认及逐镜审核通过。

## 6 文章「模型容易犯的错 → 应该怎么写」对照

| 模型容易犯的错 | 文章给的写法 | 本项目落点 |
|---|---|---|
| 一群人同时做同一个动作 | 写清谁先谁后；首帧别摆同一姿势 | 分镜体检检出「同时/一齐/众人」；首帧清单 |
| 该风做的事人自己动手 | 写清原因 + 「两只手全程没碰」 | 分镜要求动作写原因、手放哪 |
| 云/月亮/植物长出五官 | 写具体材质，只写它怎么移动 | 视频生成阶段（Comfy 工作流负责） |
| 人往反方向走 | 方向按画面写「朝画面左边」 | 分镜写法 + 体检「没写画面左/右」 |
| 一句话两种意思 | 写更具体的位置 | 分镜要求地点具体；导出清单人工核对 |
| 东西数量变了 | 数量直接写出来 | 人物「单人」、道具「单件」、负面词「多人重复」 |
| 写「不要」经常没用 | 改成正面的「画面里一直只有…」 | 提示词模板用正面句；视频提示词体检检出否定句 |
| 道具被联想用法（壶总出水） | 不让道具出现在有动作的镜头 | 导出清单人工执行 |
| 东西凭空出现 | 只用首帧里已有的东西 | 分镜要求道具交代来源；首帧清单 |
| 东西瞬移/突然飞走 | 写清它是怎么动的 | 视频生成阶段 |
| 雨/帽子/纹身拍着拍着没了 | 首帧和尾帧都画上 | 首帧清单；固定特征写左右位置 |
| 闪电画得太写实 | 写「云里闪一下白光」，剪掉开头 | 视频生成阶段 |
| 一个镜头动作太多 | 每镜只写一两个主要动作 | 分镜体检：>5 秒提示拆镜 |
| 动作时间和写的不一样 | 多留时间，后期变速对拍 | 分镜 1–5 秒；导出清单 |
| 推镜没写的明显 | 后期用代码再推一点 | 制作工作流的后期/修复任务 |
| 人的嘴自己在动 | 写明「人物不说话」 | 七段式固定写入 + 体检 |
| 写了没音乐还是混进音乐 | 片段自带声音不用，后期另加 | 视频生成阶段 |
| 结尾几帧突然跳到尾帧 | 后期选一张停住 | 尾帧对齐写进七段式 + 体检 |
| 第一帧特别锐 / 越后越暗 | 去掉第一帧 / 按首帧调色 | 制作工作流的后期/修复任务 |

另外两条工作流规矩也落了地：

| 文章规矩 | 本项目落点 |
|---|---|
| 新版本存新文件，不覆盖、不删除旧文件 | 生图旧图移到 `assets/generated/versions/`；重新生成分镜时旧 JSON 移到 `storyboard/versions/` |
| 我确认故事前不画图、确认画风前不画正式镜头 | 制作工作流记录故事和画风确认快照，改动后重新确认 |

## 7 制作链边界

审核、监督和代理已由桌面工作流以独立模型上下文顺序调用。视觉审核发送实际图片；
逐镜通过结论绑定材料指纹，改动后必须重审，生成视频必须显式批准。
色块草图、黑白总表、参考片分析、修复与后期、全片静态复核和复盘均有执行入口。

模型可能漏错；静态复核不能判断动态手感和声音，最后保留人工播放确认。
长篇改编仍默认连贯式；运动模糊使用帧混合近似，调色不含语义肤色蒙版。
详细限制见 [短剧制作工作流](短剧制作工作流.md)。

# 节奏控制与角色锚定算法

> 引擎：`src/novel_writer/core/workflow/prompts.py`
> 调用点：工作流 runner 在写作/反哺步骤注入；角色约束在 Tier 1 注入
> 测试：`tests/test_workflow.py`（部分覆盖）

## 一句话总结

两套注入式约束：**(1) 节奏控制**——按目标章节数把全书切成 7 阶段，注入当前阶段的写作/反哺要求，防止长篇节奏失控；**(2) 角色锚定**——从人物设定提取角色清单，生成「主角不得更换/角色名不得擅改/新人物须铺垫」硬约束。

## 一、节奏控制（`build_pacing_context`）

### 七阶段划分

以 `progress = n / total` 切分：

| 进度区间 | 阶段 | 阶段描述 |
|----------|------|----------|
| < 5% | 开篇铺垫 | 世界观初次展开 |
| 5–15% | 初期建立 | 核心角色登场、初始冲突 |
| 15–35% | 前期发展 | 主线冲突升级、支线铺开 |
| 35–55% | 中期推进 | 核心矛盾深化、角色成长 |
| 55–75% | 后期高潮 | 冲突白热化、伏笔回收密集 |
| 75–90% | 收束阶段 | 支线收拢、悬念解答 |
| ≥ 90% | 终章阶段 | 最终决战、全文收尾 |

输出头部：

```
=== 【节奏控制 · {阶段}】 ===
当前：第{n}章 / 共{total}章（进度{pct}%，剩余{remaining}章）
阶段：{阶段}（{描述}）
```

### 写作模式（`for_update=False`）各阶段要求

| 阶段 | 要点 |
|------|------|
| 开篇 | 世界观展示+角色塑造，不急推主线；每章有新信息/新角色 |
| 前期 | 可展支线，但每章必须推主线一步；埋伏笔 |
| 中期 | 主线持续升级，禁止停滞；支线须与主线交汇 |
| 后期高潮 | 剧情密度高，每章实质转折；开始回收伏笔，不开新支线 |
| 收束 | 支线收拢、伏笔回收；不引入新角色/新冲突 |
| 终章 | 直接推进主线结局，不插回忆/支线 |

### 反哺模式（`for_update=True`）各阶段要求

| 阶段 | 反哺约束 |
|------|----------|
| 前期（<35%） | 可补支线/新伏笔，但新支线必须与主线交汇 |
| 中期（35–55%） | **停止新增支线**，推进已有支线、逐步回收伏笔 |
| 后期高潮（55–75%） | **加速回收伏笔**，不许新增支线/伏笔，悬念须在剩余章节内解决 |
| 收束/终章（≥75%） | **严禁**新增支线/伏笔/新角色；只允许回收伏笔、解决悬念、推进主线结局 |

### 尾部硬提醒

```
【重要】本小说目标{total}章，当前是第{n}章，还剩{remaining}章。
请严格按照当前阶段的要求写作，不要提前进入下一阶段。
```

`total <= 0` 时返回空串（不注入）。

## 二、角色锚定（`build_character_constraint`）

### 角色清单提取

扫描人物设定 `##`–`####` 标题：

| 跳过 | 判据 |
|------|------|
| 章节标题 | 以 `一二三四五六七八九十` 开头 |
| 固定名单 | `核心同伴/关键对立/引导角色/关系网络/动态演进` |
| 主角识别 | 标题后 10 行内含 `主角` 或 `protagonist` → 标记 `is_protagonist` |

### 约束文本

```
【写作约束 · 角色锚定】
- 主角不得更换：本书主角是「{name}」，不得中途换主角
- 角色名不得擅改：已登场角色名必须与人物设定一致，不得改名/别名替换（除非设定中有说明）
- 新人物须铺垫：新角色登场前必须有至少1章铺垫或侧面提及，不得凭空出现
- 已登场角色：{name1}、{name2}、…
```

无识别到角色时返回空串。

> 该约束被注入 **Tier 1**（世界观层），写作步骤 prompt 中也会文字强调「严格遵守【写作约束·角色锚定】」。

## 边界与已知限制

- 阶段边界是**硬编码比例**，不感知题材（短篇/中篇比例语义不同）。
- 角色提取与 `character_sim.parse_characters` 是**两套独立解析**，跳过名单略有差异（sim 多跳过「主角」标题），长期需统一。
- `is_protagonist` 当前只用于约束文案中的主角名，无多主角支持。
- 反哺模式的约束靠 prompt 软约束，无代码级拦截。

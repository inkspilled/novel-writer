# 反模式追踪算法

> 引擎：`src/novel_writer/core/anti_patterns.py` → `AntiPatternTracker`
> 落盘：`{project}/anti_patterns.json`
> 调用点：上下文组装 Tier 2 注入写作禁忌；审稿报告 → `add_from_review`
> 测试：暂无专属测试

## 一句话总结

把审稿发现的「AI 味」问题沉淀为项目级反模式库，下次写章节时注入为**写作禁忌**约束；问题过期后自动清理。空库时回退到 7 条内置默认禁忌。

## 工作流闭环

```
审稿 Agent 报告 ──► add_from_review() ──► anti_patterns.json
                                              │
写作上下文 ◄── get_constraint_text() ◄────────┤
                                              │
                clear_resolved()（距今>10 章的 low 项）
```

## 反模式条目

```python
@dataclass
class AntiPattern:
    pattern: str            # 反模式描述
    severity: str = "medium"  # low / medium / high
    source_chapter: int = 0
    evidence: str = ""      # 原文证据
    category: str = "ai_flavor"  # ai_flavor / pacing / character / logic
```

**去重键 = `pattern` 文本**。同 pattern 再次 `add` 时只更新 `source_chapter` 与 `evidence`，不追加新条目。

## 从审稿报告提取（`add_from_review`）

逐行扫描，命中关键词 `AI感 / ai_flavor / AI味 / 模板化 / 机械化 / 不自然` 的行视为问题描述，去掉行首列表符号后作为 pattern。空行触发「收束」——把累计的 `current_issue` 写入。

当前实现：`severity` 恒为 `medium`，`category` 恒为 `ai_flavor`。**非 AI 味类问题不会被提取**。

## 约束文本生成（`get_constraint_text`）

| 场景 | 输出 |
|------|------|
| 库为空 | `【写作禁忌 · AI 味检查】` + 7 条 `DEFAULT_ANTI_PATTERNS` |
| 库非空 | `【写作禁忌 · 基于审稿反馈】` + 按严重度排序取前 8 条（附章节与证据前 50 字）+ 补齐不重复的默认禁忌 |

默认 7 条禁忌（`DEFAULT_ANTI_PATTERNS`）：

1. 避免「不禁」「忍不住」「竟然」「居然」等 AI 高频词
2. 避免每段结尾都用省略号或感叹号收束
3. 避免对话全是信息倾倒，要有言外之意和潜台词
4. 避免心理描写用「他心想」「他暗想」等直白开头
5. 避免场景描写用「映入眼帘」「放眼望去」等模板句
6. 避免情绪标签化，要用动作和细节传达
7. 避免节奏均匀，要有快慢松紧的变化

默认禁忌补齐判据：`dp[:10] in existing`（描述前 10 字子串匹配），防止与已有条目重复。

## 过期清理（`clear_resolved`）

```
保留条件: severity == "high"  OR  (current_chapter - source_chapter) <= 10
```

即：high 永不过期；medium/low 距今超过 10 章自动清除。

## 边界与已知限制

- `add_from_review` 是行级关键词匹配，会漏掉不在关键词行上的问题，也可能把无关行误收。
- `clear_resolved` **无调用方自动触发**，目前需在流程中手动调用或由 runner 在章节结束后调用（待接入）。
- `category` 字段已有 `pacing/character/logic` 枚举，但提取与约束生成均只用 `ai_flavor`，其余为预留。

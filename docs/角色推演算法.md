# 角色推演算法

> 引擎：`src/novel_writer/core/character_sim.py`
> 缓存：`{project}/sim_cache/sim_{n}.md`
> 调用点：工作流步骤 `sim`（每章，optional）；上下文组装注入 `load_sim_cache`
> 测试：`tests/test_character_naming.py`（`parse_characters`）、`tests/test_character_isolation.py`

## 一句话总结

让笔下的角色「活」起来：工作流 `sim` 步骤用通用 LLM 产出角色反应，写入 `sim_cache/sim_{n}.md`；写作上下文经 `load_sim_cache` 注入。人物设定的角色档案解析（`parse_characters`）供角色锚定复用。

## 管线

```
planning/人物设定.md + 大纲 + 前文
        │
        ▼  工作流通用 LLM 步骤 id=sim
   sim_cache/sim_{n}.md
        │
        ▼  load_sim_cache()  （加 === 角色推演 === 标记）
写作上下文（WORLD 层）
```

`sim` 步骤的 prompt / input / output 定义在 `core/workflow/definition.py`（`{"id": "sim", …, "output": "sim_cache/sim_{n}.md"}`），由 runner 通用执行，不走专用 handler。

## 角色档案解析（`parse_characters`）

**唯一权威实现**（`CHARACTER_SKIP_TITLES` 也在本模块），`prompts.build_character_constraint` 转引。扫描人物设定 Markdown：

| 行形态 | 处理 |
|--------|------|
| `##/###/#### 标题` | 视为角色名，开启新档案 |
| 跳过的标题 | `一二三四五六七八九十` 开头；`CHARACTER_SKIP_TITLES`（核心同伴/关键对立/引导角色/关系网络/动态演进/主角） |
| `性格：…` | → `personality` |
| `动机/目标/驱动力：…` | → `motivation` |
| `弱点/缺陷/矛盾：…` | → `weakness` |
| `背景：…` | → `background` |
| 标题后 10 行含「主角」/「protagonist」 | → `is_protagonist=True` |

属性行取**最后一个冒号后**的内容。

## 缓存读写

| 函数 | 语义 |
|------|------|
| 工作流 `sim` 步骤 | 通用 LLM 写 `sim_cache/sim_{n}.md`（同章重跑覆盖） |
| `load_sim_cache(dir, n)` | 读缓存；不存在/空返回 `""`；自动加 `=== 角色推演 ===` 前缀 |

**标记是压缩器识别 `sim` 类的唯一判据**（`context.compress_context` 的 `"=== 角色推演 ===" in p`）。`load_sim_cache` 保证前缀，避免正文被误标为 `other`（`other` 刻意不参与裁剪）。

## 边界与已知限制

- 推演内容由通用 LLM prompt 生成（JSON 自由文本），不解析成结构化反应；压缩按标记整块截 600 字。
- 角色档案解析最多用于角色锚定与 prompt 组装，不筛选「本章出场角色」。
- 推演步骤 optional：失败/跳过时无缓存，写作步骤仅少一块参考。

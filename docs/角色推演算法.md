# 角色推演算法

> 引擎：`src/novel_writer/core/character_sim.py`
> 缓存：`{project}/sim_cache/sim_{n}.md`
> 调用点：工作流步骤 `sim`（每章，optional）；上下文组装 Tier 3 注入推演结果
> 测试：暂无专属测试

## 一句话总结

让笔下的角色「活」起来：从人物设定提取角色档案，让 LLM 以各角色视角推演当前情境下的自然反应/决定/情绪/冲突，汇总成剧情走向建议，注入写作上下文。复用现有 LLM 调用，无需额外基础设施。

## 管线

```
planning/人物设定.md ──► parse_characters() ──► [CharacterProfile]
                                                      │
大纲/情境 ────────────────────────────────────────────┤
                                                      ▼
                                            build_sim_prompt()
                                                      │
                                                      ▼ LLM
                                            parse_sim_response()
                                                      │
                                                      ▼
                                            format_sim_text() ──► sim_cache/sim_{n}.md
                                                                          │
写作上下文 Tier 3 ◄────────────────────────────────────────────────────────┘
```

## 角色档案解析（`parse_characters`）

扫描人物设定 Markdown：

| 行形态 | 处理 |
|--------|------|
| `##/###/#### 标题` | 视为角色名，开启新档案 |
| 跳过的标题 | `一二三四五六七八九十` 开头；固定名单 `核心同伴/关键对立/引导角色/关系网络/动态演进/主角` |
| `性格：…` | → `personality` |
| `动机/目标/驱动力：…` | → `motivation` |
| `弱点/缺陷/矛盾：…` | → `weakness` |
| `背景：…` | → `background` |

属性行取**最后一个冒号后**的内容。

## 推演 Prompt（`build_sim_prompt`）

- 最多取 **5 个角色**（`characters[:5]`）
- 每角色块：名 + 性格/动机/弱点/背景（背景截 100 字）
- 要求输出 JSON：

```json
{
  "reactions": [{"character", "reaction", "decision", "emotion", "conflict_with"}],
  "plot_suggestions": ["…（3条，每条50字内）"],
  "consistency_warnings": ["…"]
}
```

## 响应解析（`parse_sim_response`）

1. 优先抽 ` ```json … ``` ` 块
2. 退化到第一个 `{…}`（DOTALL）
3. `json.loads` 失败返回**空** `PlotSimulation`（不抛异常）

## 结果文本（`format_sim_text`）

```
=== 角色推演 ===
【凌尘】情绪：坚定
  反应：…
  决定：…
  冲突对象：…

【剧情走向建议】
  1. …

【一致性警告】
  ⚠ …
```

## 缓存

| 函数 | 语义 |
|------|------|
| `save_sim_cache(dir, n, text)` | 写 `sim_cache/sim_{n}.md` |
| `load_sim_cache(dir, n)` | 读缓存；不存在返回 `""` |

工作流 `sim` 步骤产出缓存，写作步骤从 Tier 3 注入。**同章重跑覆盖**。

## 边界与已知限制

- 情境来源目前是 prompt 里的「当前情境」占位，工作流实际传入的是大纲+前文（由 runner 组装），不是独立的情境分析器。
- JSON 解析失败静默返回空结果——推演失败不影响写作，但也不会有缓存。
- 角色数硬上限 5，长篇多角色时取人物设定出现顺序的前 5 个（非「本章出场角色」筛选）。
- `format_sim_text` 的 `=== 角色推演 ===` 标记是压缩算法识别 `sim` 类的**唯一判据**，改动需同步[分层上下文组装](分层上下文组装算法.md)的标记表。
